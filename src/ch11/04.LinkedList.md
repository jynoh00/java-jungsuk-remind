# 04. LinkedList
> 배열의 기본적 자료구조에서 발생하는 문제점을 보완한 자료구조

배열은 가장 기본적 형태의 자료구조로 구조가 간단하며, 데이터를 읽어오는데 걸리는 시간(`access time`)이 빠르지만 다음과 같은 단점을 가진다.

- `크기 변경 불가` : 크기를 넘어설 경우 새로운 배열을 생성하여 복사해야 한다, 실행 속도를 위한다면 큰 배열 생성을 위해 메모리 낭비가 발생 
- `비순차적인 데이터의 추가, 또는 삭제 시 시간이 많이 걸린다` : 중간에 데이터 삽입 시, 빈자리를 위해 다른 데이터를 복사하여 이동하는 절차 필요

이를 보완하기 위해 고안된 `LinkedList` 자료구조는, 불연속적으로 존재하는 데이터를 서로 연결한 형태로 구성된다.

---

각 요소(`node`)들은 노드 자신과 연결된 다음 노드에 대한 참조와 데이터로 구성된다.

```java
class Node {
    Node next; // 다음 요소의 주소
    Object obj; // 저장된 데이터
}
```

`LinkedList`에서 데이터를 삭제하고자 할 경우, 지울 노드의 앞 연결관계(참조)를 수정하기만 하면 된다.<br>
배열에서의 경우 데이터를 이동하기 위해 복사하는 과정이 없기에 중간 데이터 삭제, 삽입 시 처리 속도가 매우 빠르다.

다만 단방향으로 이루어져있기에, 다음 요소에 대한 접근은 쉽지만 이전 요소에 대한 접근은 어렵다.<br>
따라서 이를 보완한 이중 연결 리스트(`doubly linked list`)가 존재한다.

```java
class Node {
    Node next;
    Node previous;
    Object obj;
}
```

더블링크드리스트는 링크드리스트보다 각 요소에 대한 접근, 이동이 쉽기에 더 많이 사용된다.

추가로 더블 링크드 리스트의 접근성을 보다 향상시킨 것이 더블 써큘러 링크드 리스트(`doubly circular linked list`)로<br>
단순히 더블 링크드 리스트의 첫 노드와 마지막 노드를 서로 연결시킨 것이다.

---

### LinkedList 클래스

실제 자바에서 `LinkedList`클래스는 이름과 다르게 더블 링크드 리스트로 구현되어 있는데<br>
이는 링크드 리스트의 단점인 낮은 접근성을 높이기 위한 것이다. 자세한 `LinkedList`클래스의 멤버는 자바의 정석 (p628 ~ p629) 참고

`LinkedList` 역시 `List`인터페이스를 구현했기에 `ArrayList`와 내부 구현 방법만 다를 뿐<br>
제공하는 메서드의 종류와 기능은 거의 동일하다.

`ArrayList`와 `LinkedList`의 성능 차이를 비교하여 자세히 알아보도록 하겠다.

---

`code/ArrayListLinkedListEx.java` 예제 코드를 통해<br>

```java
ArrayList<String> al = new ArrayList<>(2_000_000);
LinkedList<String> ll = new LinkedList<>();
```

`al`과 `ll`의 성능을 비교하여 보았다. `add1`은 순차적 추가이며, `add2`는 중간 추가, `remove1`은 순차적 삭제, `remove2`는 중간 삭제이다.

```shell
-- 순차적 추가 --
ArrayList: 23
LinkedList: 133

-- 중간 삽입 --
ArrayList: 1391
LinkedList: 11

-- 순차적 삭제 --
ArrayList: 6
LinkedList: 22
```

```shell
-- 순차적 추가 --
ArrayList: 25
LinkedList: 138

-- 중간 삽입 --
ArrayList: 1458
LinkedList: 11

-- 중간 삭제 --
ArrayList: 1253
LinkedList: 124
```

위 두번의 실행 결과 만으로도 다음의 내용이 확인 가능하다.

- 1. 순차적 추가 / 삭제의 경우 `ArrayList`가 `LinkedList`보다 빠르다.

- 2. 중간 데이터 추가 / 삭제의 경우 `LinkedList`가 `ArrayList`보다 빠르다.

주의할 점은 위 예제 코드에서는 `ArrayList`의 크기를 충분히 크게 설정하여 성능 실험을 진행한 것이기에<br>
`ArrayList`의 크기를 넘어서는 과정이 들어간다면, 순차적 삽입 / 삭제임에도 새로운 `ArrayList`가 생성되는 과정이 추가로 들어갈 수 있어<br>
`LinkedList`가 `ArrayList`보다 순차적 추가 / 삭제에도 더 빠를 수 있다.

---

`LinkedList`에서 특정 인덱스의 값을 얻어 오고자 할 경우, 배열보다 성능적으로 느린 것을 확인할 수 있다.

배열의 경우 각 요소들이 연속적으로 메모리상에 존재하기에 단순히 `배열의 주소 + n * 데이터 타입 크기` 연산으로 값을 얻을 수 있지만<br>
링크드리스트의 경우 참조 메모리 주소값을 순서대로 따라가야 원하는 값에 접근할 수 있는 것이다.

따라서 다루고자 하는 데이터의 개수가 변하지 않는 경우라면, `ArrayList` (읽기가 빠른)<br>
데이터 개수의 변경이 잦은 경우라면, `LinkedList` (비순차적 데이터 삽입, 삭제 시 빠른)를 활용하도록 한다.

---

두 자료구조를 함께 활용하여 각각의 장점을 이용한다면 더욱 효율적인 코드를 작성할 수 있다.

```java
// 순차적 삽입은 ArrayList를 통해
ArrayList al = new ArrayList(1_000_000);
for (int i = 0; i < 1_000_000; i++) al.add(i+"");

// 중간 삽입의 경우 LinkedList를 통해
LinkedList ll = new LinkedList(al);
for (int i = 0; i < 100_000; i++) ll.add(i/2, "X");
```

컬렉션 프레임웍에 속한 대부분의 컬렉션 클래스들은 서로 변환이 가능한 생성자를 제공하기에<br>
위 예시처럼 필요에 따라 데이터의 컬렉션을 손쉽게 변경 가능하다.
