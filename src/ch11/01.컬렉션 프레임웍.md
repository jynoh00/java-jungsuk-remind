# 01. Collection Framework
> `데이터 군을 저장하는 클래스들`을 표준화한 것

`컬렉션`은 다수의 데이터, 즉 데이터 그룹을 `프레임웍`은 표준화된 프로그래밍 방식을 의미한다.

`Vector`, `Hashtable`, `Properties`와 같은 컬렉션 클래스들을 `JDK 1.2`이전의 경우<br>
서로 다른 각자의 방식으로 처리해야 했으나, `컬렉션 프레임웍`의 등장으로

다양한 종류의 컬렉션 클래스가 추가되고 모든 컬렉션 클래스를 표준화된 방식으로 다룰 수 있도록 체계화 되었다.

- 인터페이스와 다형성을 이용한 객체지향적 설계를 통해 표준화되어 있기에
- 사용법을 익히기 편리하며, 재사용성이 높은 코드를 작성할 수 있다

---

### 컬렉션 프레임웍 핵심 `인터페이스`

컬렉션 데이터 그룹을 크게 3가지 타입이 존재한다 인식하고,<br>
각 컬렉션을 다루는데 필요한 기능을 가진 3개의 인터페이스를 정의하였다.


- `List` : 순서가 있는 데이터의 집합, 중복 허용
- `Set` : 순서를 유지하지 않는 데이터의 집합, 중복 불가
- `Map` : 키(key) - 값(value)의 쌍(pair)으로 이루어진 데이터 집합, 키 중복 불가, 값 중복 허용, 순서 유지 x

`List`, `Set`의 공통된 부분을 뽑아 `Collection` 인터페이스를 추가로 정의하였다.

( `JDK 5`부터 `Iterable`인터페이스가 추가되며, 이를 `Collection`인터페이스가 상속받도록 변경 )

<br>

컬랙션 프레임 웍의 모든 클래스들은 `List`, `Set`, `Map` 중 하나를 구현하고 있으며<br>
구현한 인터페이스의 이름이 클래스의 이름에 포함되어 있기에 이름만으로 클래스의 특징을 파악할 수 있다.

단, `Vector`, `Stack`, `Hashtable`, `Properties`와 같은<br>
컬렉션 프레임웍이 생기기 이전부터 있던 클래스들은 명명법을 따르지 않는다.

⭐ `Vector`, `Hashtable`과 같은 기존 클래스들은 설계를 변경하여 남겨져있지만<br>
⭐ 가능한 새로 추가된 `ArrayList`, `HashMap`을 사용하도록 한다.

---

### `Collection` 인터페이스에 정의된 메서드 목록

```java
boolean add(Object o)
boolean addAll(Collection c)

void clear()

boolean contains(Object o)
boolean containsAll(Collection c)

boolean equals(Object o) // 동일한 컬렉션인지 -> 왜 Collection c가 아닐까
int hashCode() // hash code 반환
boolean isEmpty()
iterator iterator()

boolean remove(Object o) // 지정 객체 삭제
boolean removeAll(Collection c) // 지정된 컬렉션의 포함된 객체들 삭제

boolean retainAll(Collection c)
// 지정된 컬렉션에 포함된 객체만을 남기며, 다른 객체들은 삭제한다. 이후 기존과 달라졌다면 true, 유지면 false
    
int size()
Object[] toArray()
Object[] toArray(Object[] a) // a 배열에 컬렉션 객체를 저장해서 반환
```

- 이 외에도 `JDK 8`부터 추가된 람다(`Lambda`), 스트림(`Stream`) 관련 메서드들이 있는데<br>
자세한 내용은 14장에서 알아보도록 한다.

- `Java API`문서를 보면 `Object`가 아닌 `E`로 표기되어있는데 `E`는 특정 타입을 의미하며<br>
`JDK 5`부터 추가된 지네릭스(`Generics`)에 의한 표기이다. 자세한 사항은 12장에서 알아보도록 한다.
