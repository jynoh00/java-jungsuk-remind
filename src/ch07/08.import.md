# 08. Import

소스 코드를 작성할 때 다른 패키지의 클래스를 사용하려면 패키지 이름이 포함된 클래스 이름을 사용해야 한다.<br>
매번 패키지 이름을 붙여서 작성하기란 불편하기에 `import`문을 통해 사용하고자 하는<br>
클래스의 패키지를 미리 명시해주어 소스 코드에 사용되는 클래스 이름에서 패키지 이름을 생략할 수 있다.

---

모든 소스 파일(`.java`)에서 `import`문은 `package`문 다음에, 그리고 클래스 선언문 이전에 위치해야 한다.<br>

일반적인 소스 파일(`.java`)의 구조

1. `package`문
2. `import`문
3. 클래스 선언

`import`문의 선언 방법은 다음과 같다.

```java
import 패키지 이름.클래스 이름;
import 패키지 이름.*;
```

동일 패키지에 여러 클래스가 사용될 때 `impoert`문을 여러 번 사용하는 대신<br>
`패키지 이름.*`을 통해 지정된 패키지에 속하는 모든 클래스를 패키지 이름 없이 사용할 수 있다.<br>

클래스 이름을 지정해주는 대신 `*`을 사용하면, 컴파일러는 해당 패키지에서 일치하는<br>
클래스 이름을 찾아야 하는 수고를 더 해야 할 것이다. 단지 그 뿐으로 `실행 시 성능상의 차이는 전혀 없다.`

// 정말일까?

> 컴파일러가 패키지 내 클래스를 탐색하는 작업이 추가되기에 컴파일 속도는 미세하게 느려질 수 있다.<br> 그러나 컴파일된 코드를 실행 시 컴파일 후 바이트 코드인 `.class`에 영향을 주지 않는다.<br>컴파일러가 이미 어떤 클래스인지 확정해놓았기에 실행 시점인 런타임 상황에서 성능상 차이가 없는 것이다.

> 그럼에도 `*` import는 런타임 성능이 아닌, 어떤 클래스가 어디에서 왔는 지 명확하지 않아 가독성이 떨어지고<br>서로 다른 패키지에 같은 이름의 클래스가 있을 때 충돌이 발생할 수 있다.

추가로 조심할 점은 `import`문에서 클래스의 이름 대신<br>
`*`을 사용하는 것이 하위 패키지의 클래스까지 포함하는 것은 아니라는 것이다.
```java
import java.util.*;
import java.text.*;
```

위 두 `import`문 대신 다음과 같이 할 수는 없는 것이다.

```java
import java.*;
```

---

```java
import java.text.SimpleDateFormat;
import java.util.Date;

class ImportEx {
    public static void main(String[] args) {
        Date today = new Date();
        
        SimpleDateFormat date = new SimpleDateFormat("yyyy/MM/dd");
        SimpleDateFormat time = new SimpleDateFormat("hh:mm:ss a");
        
        System.out.println(date.format(today));
        System.out.println(time.format(today));
    }
}
```

원래 위 예제 코드는 `import`문 없이 작성하려면

```java
java.util.Date today = new java.util.Date();
java.text.SimpleDateFormat date = new java.text.SimpleDateFormat("yyyy/MM/dd");
java.text.SimpleDateFormat time = new java.text.SimpleDateFormat("hh:mm:ss a");
```

위와 같이 코드가 길어지며 가독성 역시 떨어지게 된다.

지금까지 `System`과 `String`같은 `java.lang` 패키지의 클래스를 패키지 이름 없이 사용할 수 있었던 이유는<br>
모든 소스 파일에는 묵시적으로 다음과 같은 `import`문이 선언되어 있기 때문이다.

```java
import java.lang.*;
```

`java.lang`이 매우 빈번히 사용되는 중요 클래스들이<br>
속한 패키지이기 때문에 따로 `import`문으로 지정하지 않아도 되도록 한 것이다.

---

`import`문을 사용하면 클래스의 패키지 이름을 생략할 수 있는 것처럼<br>
`static import`문을 사용하면 `static`멤버를 호출할 때 클래스 이름을 생략할 수 있다.

특정 클래스의 `static` 멤버를 자주 사용할 때 편리하며 코드 또한 간결해진다.

```java
import static java.lang.Integer.*; //Integer 클래스의 모든 static 메서드
import static java.lang.Math.random; // Math.random() 메서드만
import static java.lang.System.out; // System.out() 메서드만
```

```java        
System.out.println(Math.random());
out.println(random()); // import static을 사용하여 간소화
```
