# 13. 참조변수와 인스턴스 연결

조상 타입의 참조변수와 자손 타입의 참조변수의 차이점은 사용할 수 있는 멤버의 개수에 있다.

`조상 클래스에 선언된 멤버 변수와 같은 이름의 인스턴스 변수를 자손 클래스에 중복으로 정의했을 때`<br>
- 조상 타입의 참조 변수로 자손 인스턴스를 참조하는 경우와
- 자손 타입의 참조 변수로 자손 인스턴스를 참조하는 경우는

서로 다른 결과를 얻는다.

⭐ `메서드의 경우` 조상 클래스의 메서드를 자손의 클래스에서 오버라이딩해도 `참조변수의 타입에 관계없이`<br>
항상 `실제 인스턴스`의 메서드(오버라이딩된)가 호출되지만

⭐ 멤버 변수의 경우 참조 변수의 타입에 따라 달라지는 것이다.

---

멤버 변수가 조상 클래스와 자손 클래스에 중복으로 정의된 경우

조상 타입의 참조 변수를 사용했을 때는 조상 클래스에 선언된 멤버 변수가 사용되고<br>
자손 타입의 참조 변수를 사용했을 때는 자손 클래스에 선언된 멤버 변수가 사용된다.

중복 정의되지 않은 경우, 조상 타입의 참조변수를 사용했을 때와 자손 타입의 참조 변수를 사용했을 때의 차이는 없다.<br>
// 책에 내용은 이러하지만, 상속 관계에서 중복되지 않은 멤버 변수가 존재하면<br>
// 결국 조상 클래스에서는 이에 접근할 수 없어 에러가 발생한다.

다음과 같은 상속관계에 있는 두 클래스를 선언한 후

```java
class Parent {
    int x = 100;

    void method() {
        System.out.println("Parent method");
    }
}

class Child extends Parent {
    int x = 200;
    void method() {
        System.out.println("Child method");
    }
}
```

아래 코드를 실행하면 주석과 같은 결과가 나온다.

```java
public class BindingEx {
    public static void main(String[] args) {
        Parent parent = new Child();
        Child child = new Child();

        System.out.println(parent.x); // 100
        parent.method(); // Child method

        System.out.println(child.x); // 200
        child.method(); // Child method
    }
}
```

서로 다른 멤버 변수를 호출하는 이유는 간단하다.<br>
자손 클래스와 조상 클래스 중 어느 클래스의 멤버를 호출해야할 지 선택의 여지가 모호한 경우<br>
참조 변수의 타입에 따라 멤버들을 사용하는 것이다. 그렇다면 모호하지 않은 상황이라면 어떨까?

```java
class Child extends Parent {
//    int x = 200;
//    void method() {
//        System.out.println("Child method");
//    }
}
```

`Child` 클래스의 구현부를 모두 주석처리한 후 단순 상속만 받게 할 경우<br>

`p.x`와 `c.x`는 모두 조상 클래스의 멤버 변수인 `100`을 출력한다.<br>
`method()` 역시 조상 클래스의 출력 결과인 `Parent method`가 출력된다.

⭐ 즉 참조 변수의 타입에 따라 결과가 달라지는 경우는 조상 멤버 변수와 같은 이름의 멤버 변수를 자손에서 중복 정의한 경우뿐이다.

---

이번엔 `Child` 클래스의 `method()`를 다음과 같이 오버라이딩한 경우 `main`에서의 결과를 분석해 보겠다.

```java
class Child extends Parent {
    int x = 200;

    void method() {
        System.out.println(x);
        System.out.println(super.x);
        System.out.println(this.x);
    }
}
```

```shell
100 // p.x
200 // p.method() : x
100 // p.method() : super.x
200 // p.method() : this.x
200 // c.x
200 // c.method() : x
100 // c.method() : super.x
200 // c.method() : this.x
```

참조 변수의 타입에 따라 달라지는 값은 오로지 `p.x`와 `c.x` 뿐이다.<br>

메서드의 실행 결과는 참조 변수 타입의 영향을 받지 않았다.<br>
이에 대해 생각해보면 `parent`, `child` 모두 실제 인스턴스는 `Child` 객체를 참조한다.<br>
따라서 메서드는 자손 객체의 메서드가 실행되고, 해당 객체에서 `this`와 `super` 참조변수를 사용한 것이기에<br>
`Child` 객체의 멤버 변수와 조상 변수의 값들이 호출되는 것이다.

---

⭐ 일반적으로 멤버 변수는 `private` 접근 제어자를 사용하고, 외부에서는 `get`, `set`과 같은 메서드를 통해<br>
멤버 변수에 접근할 수 있도록 한다. 이번 예제처럼 외부에서 참조변수를 통해 직접 인스턴스 변수에 접근하면<br>
참조 변수의 타입에 따라 사용되는 인스턴스 변수가 달라지기에 메서드를 통한 멤버 변수 접근의 이유를 살펴볼 수 있다.

( 메서드는 참조 변수의 타입에 영향을 받지 않는다. )
