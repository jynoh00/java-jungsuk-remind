# 17. 인터페이스 1
> 인터페이스(`interface`)는 일종의 추상 클래스이다.

인터페이스는 추상 클래스와 마찬가지로 추상 메서드를 갖지만, 추상 클래스보다 추상화 정도가 높아서<br>
추상클래스와 다르게 몸통을 갖춘 `일반 메서드` 또는 `멤버 변수`를 구성원으로 가질 수 없다.

오직 `추상 메서드`와 `상수`만을 멤버로 가질 수 있는데, 상수는 부수적이고 `추상 메서드가 핵심`이다.

추상클래스가 부분적으로 완성된 추상 `미완성 설계도`라 하면, 인터페이스는 구현된 것은 아무 것도 없고<br>
밑그림만 그려져 있는 `기본 설계도`라 할 수 있다.

---

```java
interface 인터페이스이름 {
    public static final 타입 상수이름 = 값;
    public abstract 메서드이름(매개변수목록);
}
```

`인터페이스`는 클래스를 작성하는 것과 동일하다. 다만 키워드로 `interface`를 사용한다는 것이 다르다.<br>
또한 `interface`에도 클래스와 마찬가지로 접근 제어자로 `public`, `(default)`를 사용할 수 있다.

일반적인 클래스 멤버와의 차이점은 다음과 같이 제약사항이 존재한다.

- 모든 멤버변수는 `public static final` 이며 생략할 수 있다.
- 모든 메서드는 `public abstract`이며 생략할 수 있다.

( 위 제약사항에서 static메서드와 디폴트 메서드(`JDK 8`), 그리고 `private`메서드(`JDK 9`)는 예외이다. `p.430` )

아래처럼 인터페이스의 멤버에 제어자를 생략하면 컴파일시 컴파일러가 자동으로 추가하여 준다.

```java
interface PlayingCard {
    public static final int SPADE = 4;
    final int DIAMOND = 3; // public static final int DIAMOND = 3;
    static int HEART = 2; // public static final int HEART = 2;
    int CLOVER = 1; // public static final int CLOVER = 1;
    
    public abstract String getCardNumber();
    String getCardKind(); // public abstract String getCardKind();
}
```

본래 인터페이스의 모든 메서드는 추상 메서드여야 하는데, `JDK 8`부터 인터페이스에 `static`메서드와 `(default)`메서드를<br>
`JDK 9`부터 `private`메서드의 추가를 허용하였다. 허나 이들은 부수적이며 핵심은 여전히 추상 메서드이고

⭐ 인터페이스는 추상 메서드의 집합이다.

---

인터페이스는 `인터페이스로부터만` 상속이 가능하다.<br>
또한 클래스와 다르게 `다중 상속`이 가능하다.

```java
interface Movable {
    void move(int x, int y);
}

interface Attackable {
    void attack(Unit u);
}

interface Fightable extends Movable, Attackable { }
```

클래스의 상속과 동일하게 자손 인터페이스는 조상 인터페이스에 정의된 멤버를 모두 상속 받는다.<br>
따라서 위 코드에서 `Fightable` 인터페이스 자체에는 정의된 멤버가 하나도 없지만<br>
상속받은 두 개의 추상 메서드를 멤버로 가지게 된다.

---

또한 인터페이스는 추상 클래스처럼 그 자체로는 인스턴스를 생성할 수 없기에<br>
인터페이스 자신에 정의된 추상 메서드의 구현부를 완성해주는 클래스를 만들어야 인스턴스 생성이 가능하다.

클래스에서는 확장의 의미를 갖는 `extends`를 활용했지만,<br>
인터페이스에서는 구현한다는 의미의 키워드 `implemnents`를 사용한다.

```java
class 클래스이름 implements 인터페이스이름 {
    // 추상 메서드 구현
}

class Fighter implements Fightable {
    public void move(int x, int y) { /* 구현 */ }
    public void attack(Unit u) { /* 구현 */ }
}
```

구현하는 인터페이스의 메서드 중 일부만 구현한다면, `abstract`를 붙여 추상 클래스로 선언이 가능하다.

```java
abstract class Fighter implements Fightable {
    public void move(int x, int y) { /* 구현 */ }
}
```

또한 자손 클래스에서 조상 클래스의 상속과, 인터페이스의 구현이 동시에 가능하다.

```java
class Fighter extends Unit implements Fightable {
    public void move(int x, int y) { /* 구현 */ }
    public void attack(Unit u) { /* 구현 */ }
}
```

⭐ ( 인터페이스의 이름에는 주로 `~을 할 수 있는`의 의미인 `able`로 끝나는 것들이 많다 )<br>
⭐ ( 이유는, 어떠한 기능 또는 행위를 하는데 필요한 메서드를 제공한다는 의미이다. )<br>
⭐ ( 또한 그 인터페이스를 구현한 클래스는 `~을 할 수 있는` 능력을 갖추었다는 의미를 가진다. )
