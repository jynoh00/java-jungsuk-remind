# 18. 인터페이스 2
> 자바(Java)에서의 다중상속

다른 객체지향언어의 다중 상속에 대하여 `자바도 인터페이스를 이용하면 다중 상속이 가능하다`는 대응적 의미일 뿐<br>
자바에서 `실제로 인터페이스로 다중 상속을 구현하는 경우는 거의 없다`.

인터페이스는 `static`상수만 정의할 수 있으므로 조상 클래스의 멤버 변수와 충돌하는 경우는 거의 없고<br>
충돌된다 하여도 클래스 이름을 붙여서 구분이 가능하다. (`static` 멤버 사용 시)

또한 추상 메서드는 구현 내용이 전혀 없기에, 조상 클래스의 메서드와 선언부가 일치하는 경우에는<br>
당연히 조상 클래스 쪽 메서드를 상속 받으면 되기에 문제가 되지 않는다.<br>
그러나 이러한 방법은 상속 받는 멤버의 `충돌을 피할 수 있지만`, `다중 상속의 장점을 잃게` 된다.

만일 두 개의 클래스로부터 상속을 받는 상황이라면

- 두 조상 클래스 중 비중이 높은 쪽을 선택하고
- 다른 한쪽은 클래스 내부에 멤버로 포함시키는 방식으로 처리

혹은 어느 한쪽의 필요 부분을 뽑아 인터페이스로 만든 후 구현하도록 한다.

```java
public class Tv {
    protected boolean power;
    protected int channel;
    protected int volume;
    
    public void power() { power = !power; }
    public void channelUp() { channel++; }
    public void channelDown() { channel--; }
    public void volumeUp() { volume++; }
    public void volumeDown() { volume--; }
}

public class DVD {
    protected int counter;
    
    public void play() { /* 생략 */ }
    public void stop() { /* 생략 */ }
    public void reset() { /* 생략 */ }
    public int getCounter() { return counter; }
    public void setCounter(int c) { counter = c; }
}
```

위와 같이 `Tv`, `DVD` 클래스가 존재할 때 `TvDVD` 클래스를 작성하기 위해<br>
두 클래스 동시에 다중 상속이 불가능하기에, 한 쪽만 선택하여 상속받고 나머지 한 쪽은<br>
클래스 내에 포함시켜 내부적으로 인스턴스를 생성해서 사용한다.

`DVD` 클래스에 정의된 메서드와 일치하는 추상 메서드를 갖는 인터페이스를 작성한다.
```java
public interface IDVD {
    public void play();
    public void stop();
    public void reset();
    public int getCounter();
    public void setCounter(int c);
}
```

`IDVD` 인터페이스를 구현하고 `Tv` 클래스를 상속 받는 `TvDVD` 클래스를 작성해준다.

```java
public class TvDVD extends Tv implements IDVD {
    DVD dvd = new DVD();
    
    public void play() { dvd.play(); }
    public void stop() { dvd.stop(); }
    public void reset() { dvd.reset(); }
    public int getCounter() { return dvd.getCounter(); }
    public void setCounter(int c) { dvd.setCounter(c); }
}
```

사실 인터페이스를 새로 작성하지 않고도 `DVD`클래스를 `TvDVD`에 포함시키는 것만으로도 충분하지만<br>
인터페이스를 이용할 경우 다형적 특성을 이용할 수 있다는 장점이 있다.

즉, `TvDVD` 인스턴스를 `IDVD` 타입으로 취급이 가능하며, 동시에 `Tv` 타입으로도 취급이 가능하다는 것이다.

소스 코드 : `code/tvdvdex/`

---

이전에 다형성에 대해 학습할 때, 자손 클래스의 인스턴스를 조상 타입의 참조변수로 참조하는 것이 가능하다 배웠다.

인터페이스 역시, 이를 구현한 클래스의 조상이라 할 수 있기에<br>
해당 `인터페이스 타입의 참조 변수`로 이를 `구현한 클래스의 인스턴스`를 `참조`할 수 있다.

```java
Fightable f = (Fightable) new Fighter();
// or
Fightable f = new Fighter();
```

`Fightable` 타입의 참조변수 `f`로는 인터페이스 `Fightable`에 정의된 멤버들만 사용이 가능하다.<br>

// `Fightable` 인터페이스를 구현한 `Fighter`클래스의 메서드가<br>
// `오버라이딩 된 것`이기에 동적바인딩되었다 볼 수 있는 것이다.

---

따라서 인터페이스의 참조변수로 실체가 있는 인스턴스의 형변환이 가능하기에<br>
매개변수의 타입으로도 인터페이스가 사용이 가능하다.

```java
void attack(Fightable f) {
    // ...
}
```

인터페이스 타입의 매개변수가 갖는 의미는 다음과 같다.

⭐ 메서드 호출 시 해당 인터페이스를 구현한 클래스의 인스턴스를 매개변수로 제공해야한다는 것이다.

따라서 `attack`메서드를 호출하고자 할 때는, 매개변수로 `Fightable` 인터페이스를 구현한<br>
클래스의 인스턴스를 넘겨주어야 한다.

```java
class Fighter extends Unit implements Fightable {
    public void move(int x, int y) { /* 생략 */ }
    public void attack(Fightable f) { /* 생략 */ }
}
```

위 코드처럼, 인터페이스를 구현한 클래스가 있을 때<br>
`attack()`메서드의 매개변수로 `Fighter` 클래스의 인스턴스를 넘겨줄 수 있는 것이다.

```java
Fighter f = new Fighter();
f.attack(new Fighter());
```

---

메서드의 리턴타입을 활용해 인터페이스의 타입을 지정하는 것 또한 가능하다.

```java
Fightable method() {
    ...
    return new Fighter();
}
```

⭐ `리턴타입이 인터페이스라는 것`은 메서드가 해당 인터페이스를 구현한 클래스의 인스턴스를 반환한다는 것이다.

즉 위 코드에서는 `method()`가 리턴타입이 `Fightable` 인터페이스이기 때문에,<br>
`Figtable`인터페이스를 구현한 `Fighter`클래스의 인스턴스를 반환한다.

// 반환한 값을 활용한다면, 참조변수가 `Fightable`인터페이스 타입이기에<br>
// 인터페이스에 있는 멤버만 접근이 가능하게 된다.<br>
// 주의할 점은 그럼에도 실체는 메모리 어딘가 생성된 `Fighter` 객체라는 것이다.

전체 코드 : `code/ParserEx.java`

```java
...

class ParserManager {
    public static Parseable getParser(String type) {
        if (type.equals("XML")) return new XMLParser();
        
        return new HTMLParser();
    }
}

...
```

위 예제 코드를 포함한 전체 코드에서<br>
추후 새로운 종류의 XML구문 분석기 `NewXMLParser`클래스가 나오는 상황을 가정하더라도<br>
클라이언트에 해당하는 `ParserEx`클래스는 변경할 필요가 없어 `ParserManager`클래스의<br>

`getParser()`메서드만

```java
return new NewXMLParser();
```

로 변경해주면 된다. ( `NewXMLParser`클래스 역시 `Parserable` 인터페이스의 구현체이기 때문 )

이러한 장점은 분산 환경에서 큰 위력을 발휘한다. 사용자 컴퓨터에 설치된 프로그램을 변경하지 않고<br>
서버측의 변경만으로 사용자가 새로 개정된 프로그램을 사용하는 것이 가능하다.
