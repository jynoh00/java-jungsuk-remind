# 16. 추상 클래스
> 추상 클래스(`abstract class`)란 미완성 설계도에 비유할 수 있다.

단어의 뜻 그대로 완성되지 못한 채로 남겨진 설계도를 말한다.<br>
클래스가 미완성이란 것은 멤버의 개수에 관계된 것이 아닌, 미완성 메서드(추상 메서드)를 포함하고 있다는 의미이다.

미완성 설계도로 제품을 만들 수 없듯이, 추상 클래스로 인스턴스를 생성할 수 없다.<br>
상속을 통해서 자손 클래스에서 완성되어야 인스턴스를 만들 수 있다.

클래스로서의 역할을 다하지 못하는 추상 클래스지만<br>
새로운 클래스를 작성할 때 있어 바탕이 되는 조상으로서 중요한 의미를 가진다.

실생활에서 생각해보면 동일 분류의 제품들을 만들 때 대부분을 일치하는 설계를 가질 것이다.<br>
이렇듯 일치하는 부분을 그린 미완성 설계도를 만들어 놓고 이를 활용해 각각의 설계도를 완성하는 것이 효율적일 것이다.

---

추상 클래스는 키워드 `abstract`만 붙이면 된다. 이렇게 함으로 이 클래스를 이용할 때<br>
선언부를 본 후 이 클래스에는 추상 메서드가 있으니 상속을 통해 구현해주어야 한다는 것을 알 수 있는 것이다.

```java
abstract class 클래스 이름 {
    ...
}
```

추상 클래스는 추상 메서드를 포함하고 있다는 것을 제외하면 일반 클래스와 전혀 다르지 않다.<br>
추상 클래스에도 생성자가 있으며, 멤버 변수와 메서드도 가질 수 있다.

( 추상 메서드가 없는 클래스도 `abstract` 키워드를 붙여 추상 클래스로 만들 수 있다 )<br>
( 추상 메서드가 없는 완성된 클래스라도 추상 클래스로 지정되면 인스턴스를 생성할 수 없다 )

---

추상 메서드 (`abstract method`)는 선언부와 구현부로 나누어져 있는 일반 메서드에서<br>
선언부만 작성 후 구현부를 남겨 둔 것이라 할 수 있다.

이러한 미완성 메서드를 사용하는 이유는 메서드의 내용이 상속 받는 내용에 따라 달라질 수 있기에<br>
조상에는 `선언부만 작성하고`, `주석을 덧붙여` 어떤 기능을 수행할 목적으로 작성되었는 지 알려주고<br>
실제 내용은 상속받는 자손에서 구현하도록 비워두는 것이다.

추상 메서드 역시 `abstract` 키워드를 앞에 붙여 주고, 괄호(`{}`) 대신 세미콜론(`;`)을 적어 문장을 마친다.

```java
/* 주석을 통한 메서드 기능, 목적 설명 */
abstract 리턴타입 메서드이름();
```

이후 상속 받는 자손 클래스에서 오버라이딩을 통해 추상 메서드를 `모두` 구현해야 한다.

만일 하나라도 구현하지 않을 경우, 자손 클래스 역시 추상 클래스로 지정해야 한다.

```java
abstract class Player {
    abstract void play(int pos);

    abstract void stop();
}

class AudioPlayer extends Player {
    void play(int pos) {
        ...
    }
    
    void stop() {
        ...
    }
}

abstract class AbstractPlayer extends player {
    void play(int pos) {
        ...
    }
}
```

메서드의 `이름`과 메서드의 작업에 필요한 `매개변수`, `반환값`을 결정하는 일은 쉽지 않다.<br>
선언부만 작성하여도 메서드의 절반 이상이 완성되는 것이라 할 수 있다.<br>
추상 메서드는 어쩌면 구현부보다 더 중요한 선언부를 작성하는 것이기에 매우 중요하다.

---

```java
abstract class Player {
    abstract void play(int pos);
    abstract void stop();
}
```

```java
class Player {
    void play(int pos) {}
    void stop() {}
}
```

위 두 조상 클래스는 모두 메서드의 구현부를 작성하지 않았다.<br>
결국 상속을 통해 자손 클래스에서 동작이 구현되는데, 왜 굳이 `abstract`를 사용하는 것일까?

이유는 `강제성을 부여`하기 위해서이다.<br>
추상 메서드로 정의되어 있지 않고 빈 몸통만 가지도록 정의되어 있다면<br>
상속 받는 자손 클래스에서는 해당 메서드들이 온전히 구현된 것으로 인식하고 오버라이딩을 통해<br>
자신의 클래스에 맞도록 `구현하지 않을 수도 있기 때문`이다.

---

```java
class Marine {
    int x, y;
    void move(int x, int y) { /* 생략 */ }
    void stop() { /* 생략 */ }
    void stimPack() { /* 생략 */ }
}

class Tank {
    int x, y;
    void move(int x, int y) { /* 생략 */ }
    void stop() { /* 생략 */ }
    void changeMode() { /* 생략 */ }
} 

class Dropship {
    int x, y;
    void move(int x, int y) { /* 생략 */ }
    void stop() { /* 생략 */ }
    void load() { /* 생략 */ }
    void unload() { /* 생략 */ }
}
```

위 클래스들을 살펴보면, 기능상 공통적인 부분들이 존재한다.<br>
이를 뽑아내어 하나의 클래스로 만들고, 이 클래스로부터 상속받도록 추상화하면 아래와 같이 수정할 수 있다.

```java
abstract class Unit {
    int x, y;
    abstract void move(int x, int y);
    void stop() { /* 생략 */ }
}

class Marine extends Unit {
    void move(int x, int y) { /* 생략 */ }
    void stimPack() { /* 생략 */ }
}

class Tank extends Unit {
    void move(int x, int y) { /* 생략 */ }
    void changeMode() { /* 생략 */ }
} 

class Dropship extends Unit {
    void move(int x, int y) { /* 생략 */ }
    void load() { /* 생략 */ }
    void unload() { /* 생략 */ }
}
```

각 유닛들은 공중 유닛과, 지상 유닛이 다르기에 실제 `move()` 동작의 구현이 다를 것이다.<br>
따라서 자손 클래스에서 나뉘어지는 기능들은 추상 메서드로 설정하고<br>
공통적으로 사용되는 `x`, `y`, `stop()` 멤버들은 `abstract`를 붙이지 않아 `Unit` 추상 클래스로 설정하였다.

공통 조상 클래스로부터 상속 받게 하였기에, 여러 유닛들을 다루기 위한 참조변수 배열을 사용할 수 있다.

```java
Unit[] group = new Unit[4];

group[0] = new Marine();
group[1] = new Tank();
group[2] = new Marine();
group[3] = new Dropship();

for (int i = 0; i < group.length; i++) {
    group[i].move(100, 200);
}
```

`group[i].move(100, 200);`에서 오버라이딩된 각 인스턴스의 메서드가 실행되어 기능이 수행된다.<br>

`Object` 타입 참조 변수 배열로도 인스턴스를 묶을 수 있겠으나

```java
Object[] group = new Object[4];

group[0] = new Marine();
group[1] = new Tank();
group[2] = new Marine();
group[3] = new Dropship();

for (int i = 0; i < group.length; i++) {
    group[i].move(100, 200); // error
}
```

반복문 내 `move()`를 실행할 때 에러가 발생한다. <br>
`ch07/15.다양한 객체 배열.md`에서 설명했듯이 `Object` 클래스에 `move`메서드가 정의되어 있지 않아<br>
동적 바인딩이 이루어지지 않아 에러가 발생하는 것이다.
