# 06. super

`super`는 자손 클래스에서 조상 클래스로부터 상속받은 멤버를 참조하기위해 사용되는 `참조변수`이다.<br>
앞서 멤버 변수와 지역 변수의 이름이 같을 때 `this`를 붙여 구별했듯이

⭐ 상속받은 멤버와 자신의 멤버가 이름이 같을 때 `super`를 붙여 구별할 수 있다.

`super`와 `this`는 무엇을 구별하냐의 차이지 근본적으로 같다.<br>
모든 인스턴스 메서드에는 자신이 속한 인스턴스의 주소 가 지역변수로 저장되는데,<br>
이것이 참조변수인 `this`, `super`의 값이 된다. 

`this`와 마찬가지로 `super` 역시 `static`메서드에서 사용할 수 없고 인스턴스 메서드에서만 사용 가능하다.

// this는 클래스로부터 생성된 인스턴스 메서드에서 호출할 수 있는데,<br>
// super는 자손 인스턴스를 만들어도 조상 인스턴스를 만들지 않았는데 어떻게 참조할 수 있는가?

> ⭐ 자손 클래스를 만들 때 조상 클래스 부분도 함께 생성된다. 즉 조상 인스턴스를 따로 만드는 것이 아닌<br>자손 인스턴스 안에 조상 인스턴스 부분이 포함되는 것이다. this와 super는 둘 다 같은 객체 주소를 참조하는데<br>
컴파일러가 어떤 클래스의 필드/메서드를 참조할 지 결정한다.<br>
<br>
같은 객체 안에 필드가 이름은 같지만 두 개 존재하고, 컴파일러가 super 키워드를 만나면<br>
오프셋을 부모 클래스 영역으로 잡아주는 것이다. 

> ⭐ 그렇다면 서로 같은 주소를 참조하는 this와 super를 print해보면 어떤 결과가 나올까<br>
결과적으로 this와 super.toString()은 같은 자식 인스턴스를 가리킨다. 왜 super는 단일로 안 써지고 toString()을<br>
통해 값을 얻어야만 하나?

> ⭐ super와 this는 본질적으로 차이점을 가지고 있기 때문이다. super는 사실 참조변수가 아니다.<br>
참조변수처럼 보이지만 컴파일러에게 "부모 클래스 멤버를 봐라" 지시하는 키워드에 해당한다.<br>
즉 super는 사실 타입도 값도 없는 순수한 문법적 키워드이기에 println(super)가 불가능한 것이다.<br>
<br>
자바 언어 명세를 확인한 결과 + 자바의 정석 p.45의 키워드 목록을 보면 super는 키워드라 정의되어 있다.<br>
그런데 this 역시 키워드에 정의되어 있었다. 그렇다면 this는 super처럼 그저 순수 문법적 키워드가 아닌걸까?
<br><br>
this도 사실은 키워드지만 현재 객체의 참조값을 나타내는 표현식(Primary Expression)으로도 동작하도록<br>
자바 언어 명세에서 정의되어 있기에 println(this)가 가능한 것이다.

---

```java
class SuperEx {
    public static void main(String[] args) {
        Child c = new Child();
        c.method();
    }
}

class Parent { int x = 10; }

class Child extends Parent {
    int x = 20;
    
    void method() {
        System.out.println(x); // 20
        System.out.println(this.x); // 20
        System.out.println(super.x); // 10
    }
}
```

`super.x`와 `this.x`는 서로 다른 값을 참조하게 된다.<br>
이처럼 조상 클래스에 선언된 멤버변수와 같은 이름의 멤버 변수를 자손 클래스에서 중복해서 정의하는 것이 가능하며

참조변수 `super`를 이용하여 서로 구별할 수 있다.

---

멤버 변수 뿐만 아니라 메서드 역시 `super`를 사용하여 호출할 수 있다.<br>
특히 조상의 메서드를 자손 클래스에서 오버라이딩한 경우에 `super`를 사용한다.

```java
class Point {
    int x, y;
    String getLocation() {
        return "x:" + x + "y:" + y;
    }
}

class Point3D {
    int z;
    String getLocation() {
        super.getLocation() + "z:" + z;
    }
}
```

`getLocation()`을 오버라이딩할 때 조상 클래스의 getLocation()을 호출하는 코드를 포함시켰는데

이를 통해 후에 조상클래스의 메서드가 변경되더라도 변경된 내용이 자손클래스의 메서드에<br>
자동적으로 반영될 수 있어 조상 클래스 메서드 변경으로 모든 자식 클래스를 변경해야하는 수고를 덜 수 있다.

---

`super()`는 `this()`와 마찬가지로 생성자이며, 조상 클래스의 생성자를 담당한다.<br>
`this()`는 같은 클래스의 다른 생성자를 호출하고자 할 때 사용되고,<br>
`super()`는 조상 클래스의 생성자를 호출하는데 사용된다.

자손 클래스의 인스턴스를 생성하면, 자손의 멤버와 조상의 멤버가 모두 합쳐진 하나의 인스턴스가 생성된다.<br>
따라서 자손 클래스의 인스턴스가 조상 클래스의 멤버들을 사용할 수 있는 것이다.

⭐ 이때 조상 클래스 멤버의 초기화 작업이 수행되어야 하기에 자손클래스의 생성자에서 조상 클래스의 생성자가 호출되어야 한다. 

이와 같은 조상 클래스 생성자의 호출은 클래스의 상속 관계를 거슬러 올라가며 계속 반복된다.<br>
마지막으로 최고 조상인 `Object`클래스의 생성자인 `Object()`까지 가서야 끝이 난다.

---

따라서 `Object`클래스를 제외한 모든 클래스의 생성자는 첫 줄에 반드시<br>
자신의 다른 생성자 또는 조상의 생성자를 호출해야 한다.

⭐ 그렇지 않으면 컴파일러는 생성자의 첫 줄에 `super();`를 자동적으로 추가한다. (`Object`클래스 제외)

```java
class PointEx {
    public static void main(String[] args) {
        Point3D p3 = new Point3D(1, 2, 3);
    } 
}

class Point {
    int x, y;
    
    Point(int x, int y) {
        this.x = x;
        this.y = y;
    }
    
    String getLocation() {
        return "x:" + x + "y:" + y;
    }
}

class Point3D extends Point {
    int z;
    
    Point3D(int x, int y, int z) {
        // error
        this.x = x;
        this.y = y;
        this.z = z;
    }
    
    String getLocation() {
        return super.getLocation() + "z:" + z;
    }
}
```

위 코드는 `Point3D` 생성자 첫 줄에서 다른 생성자를 호출하지 않기에<br>
컴파일러가 `super();`를 삽입한다. 그러나 `Point` 클래스에는<br>
`Point()` 생성자가 존재하지 않아 컴파일 에러가 발생한다. 

```bash
java: constructor Point in class oop2.Point cannot be applied to given types;
  required: int,int
  found:    no arguments
  reason: actual and formal argument lists differ in length
```

`Point3D`클래스의 생성자 첫 줄이 생성자(조상의 or 자신의)를 호출하는 문장이 아닌 경우<br>
컴파일러는 자동적으로 `super();`를 생성자 첫 줄에 넣어준다.

이를 해결하기 위해선 `Point` 클래스에 `Point()` 생성자를 추가해주던가,<br>
`Point3D(int x, int y, int z)`의 첫 줄에서 `Point(int x, int y)`를 호출하도록 변경하면 된다.

```java
Point3D(int x, int y, int z) {
    super(x, y);
    this.z = z;
}
```

⭐ 조상 클래스의 멤버 변수는 이처럼 조상의 생성자에 의해 초기화되게 하는 것이 좋다.

---

최종적으로 `Point3D p3 = new Point3D(1, 2, 3);`와 같이 인스턴스를 생성하면,<br>
아래의 순서로 생성자가 호출된다.

```
Point3D(int x, int y, int z) -> Point(int x, int y) -> Object()
```

`Point(int x, int y)` 생성자의 첫 줄에 어떤 생성자도 호출하고 있지 않기에<br>
컴파일러가 `super();` 코드를 넣고, 조상인 `Object`클래스의 생성자 `Object()`를 호출하는 것이다.
