# 01. 예외 클래스
> 자바에서는 실행 시 발생할 수 있는 오류(`Exception`, `error`)를 클래스로 정의하였다.

모든 클래스의 조상은 `Object`이므로 `Exception`과 `error`클래스 역시 `Object`클래스의 자손들이다.

이러한 예외 클래스의 계층 구조는 다음과 같다.

`Object`
- `Throwable`
  - `Exception`
    - `RuntimeException`
    - `IOException`
    - ...
  - `Error`
    - `OutOfMemoryError`
    - ...

( `Throwable`은 인터페이스가 아닌 클래스이며 `Exception`과 `error`의 공통 조상이다 )

---

모든 예외의 최고 조상은 `Exception`클래스이며, 상속계층도를 `Exception`부터 나타내면 아래와 같다.

`Exception`
- `IOException`
- `ClassNotFoundException`
- ...
- `RuntimeException`
  - `ArithmeticException`
  - `ClassCastException`
  - `NullPointerException`
  - ...
  - `IndexOutOfBoundsException`

예외 클래스들은 크게 두 그룹으로 나눌 수 있다.

1. `Exception`클래스와 자손들 (`RuntimeException`과 자손들 제외)
2. `RuntimeException`클래스와 자손들

---

런타임 예외 클래스들은 주로 프로그래머의 실수에 의해 발생될 수 있는 예외들로 자바의 프로그래밍 요소들과 관계가 깊다.

- Ex1. 배열 범위를 벗어남 (`ArrayIndexOutOfBoundsException`)<br>
- Ex2. null값인 참조변수의 멤버 호출 (`NullPointerException`)<br>
- Ex3. 클래스간 잘못된 형변환 (`ClassCastException`)<br>
- Ex4. 정수를 0으로 나눌 때 (`ArithmeticException`)

런타임 예외가 아닌 예외 클래스들은 주로 외부의 영향으로 발생하는 것들로<br>
프로그램의 사용자들의 동작에 의해서 발생하는 경우가 많다.

- Ex1. 존재하지 않는 파일의 이름 입력 (`FileNotFoundException`)
- Ex2. 잘못된 클래스 이름 입력 (`ClassNotFoundException`)
- Ex3. 잘못된 데이터 형식 (`DataFormatException`)

⭐ `RuntimeException`클래스들 : 프로그래머의 실수로 발생하는 예외<br>
⭐ 런타임 예외 제외 `Exception`클래스들 : 프로그래머의 실수로 발생하는 예외
