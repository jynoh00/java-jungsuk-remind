# 06. 자동 자원 반환
> `JDK 7`부터 `try-with-resources`문이라는 `try-catch`문의 변형이 추가되었다

`try-with-resources`문은 입출력과 관련된 클래스를 사용할 때 유용한데<br>
입출력에 사용되는 클래스 중 사용한 후에 사용했던 자원(`resources`)이 반환되기 위해<br>
꼭 사용 후에 닫아줘야 하는 클래스들이 존재한다.

```java
try {
    fis = new FileInputStream("score.dat");
    dis = new DataInputStream(fis);
} catch(IOException ie) {
    ie.printStackTrace();
} finally {
    dis.close();
}
```

기존 `try-catch-finally`를 사용하면 위와 같이 나타낼 수 있는데

`DataInputStream`을 통해 데이터를 읽는 도중에 예외가 발생하더라도 `DataInputStream`이 닫히도록<br>
`finally`블럭 안에 `close()`를 넣었다.

⭐ 여기서 `close()`메서드가 예외를 발생시킬 수 있다는 문제점이 존재한다.

따라서 위 코드는 아래처럼 변경하여야 한다.

```java
try {
    fis = new FileInputStream("score.dat");
    dis = new DataInputStream(fis);
} catch (IOException ie) {
    ie.printStackTrace();
} finally {
    try {
        if (dis != null) dis.close();
    } catch (IOException ie) {
        ie.printStackTrace();
    }
}
```

`finally`블럭 내에 `try-catch`문을 추가하여 `close()`에서 발생할 수 있는 예외를 처리하도록 하였는데<br>
코드의 복잡도가 늘어나 가독성이 떨어진다.

더 큰 문제는 `try`블럭과 `finally`블럭에서 모두 예외가 발생하면, `try`블럭의 예외는 무시된다는 것이다.

⭐ `try-catch`문 끝에 선택적으로 덧붙여 사용 가능하며, `try-catch-finally`순으로 구성된다.

```java
try {
    throw new NullPointerException("try"); // 해당 예외는 무시된다
} finally {
    throw new RuntimeException("finally"); // 해당 예외만 발생
}
```

```shell
Exception in thread "main" java.lang.RuntimeException: finally
```

---

이러한 점을 개선하기 위해 `try-with-resources`문이 추가된 것이다.

```java
try (FileInputStream fis = new FileInputStream("score.dat");
    DataInputStream dis = new DataInputStream(fis)) {
    while (true) {
        score = dis.readInt();
        System.out.println(score);
        sum += score;
    }
} catch (EOFException e) {
    System.out.println("점수 총합 : " + sum);
} catch (IOException ie) {
    ie.printStackTrace();    
}
```

( `try` 블럭의 괄호`()`안에 변수를 선언하는 것도 가능하다, 선언된 변수는 `try`블럭 내에서만 사용 가능 )

`try-with-resources`문의 괄호안에 객체를 생성하는 문장을 넣으면<br>
이 객체는 따로 `close()`를 호출하지 않아도 `try`블럭을 벗어나는 순간 자동적으로 `close()`가 호출된다.

그 다음에 `catch`블럭 또는 `finally`블럭이 수행된다.

⭐ 이처럼 `try-with-resources`문에 의해 자동으로 객체의 `close()`가 호출되려면<br>
⭐ 클래스가 `AutoCloseable`이라는 인터페이스를 구현한 구현체여야 한다.

```java
public interface AutoCloseable {
    void close() throws Exception;
}
```

위 인터페이스는 각 클래스에서 적절히 자원 반환 작업을 하도록 구현되어 있다.<br>
⭐ 그런데 위 인터페이스를 보면 자동 호출된 `close()`도 `Exception`을 발생시킬 수 있다.

`code/TryWithResourceEx.java` 코드를 통해 이와 같은 상황에 대해 살펴보겠다.

코드의 전체 실행 결과는 아래와 같다.

```shell
exceptionWork(false) 호출됨
close() 호출됨
exceptionWork(true) 호출됨
close() 호출됨
ch08.CloseException: CloseException 발생
	at ch08.CloseableResource.close(TryWithResourceEx.java:33)
	at ch08.TryWithResourceEx.main(TryWithResourceEx.java:7)
ch08.WorkException: WorkException 발생
	at ch08.CloseableResource.exceptionWork(TryWithResourceEx.java:28)
	at ch08.TryWithResourceEx.main(TryWithResourceEx.java:17)
	Suppressed: ch08.CloseException: CloseException 발생
		at ch08.CloseableResource.close(TryWithResourceEx.java:33)
		at ch08.TryWithResourceEx.main(TryWithResourceEx.java:16)
```

`main`메서드의 첫 `try-catch`문에서는 `close()`에서만 예외를 발생시키고<br>
두 번째 `try-catch`문에서는 `exceptionWork()`와 `close()`에서 모두 예외를 발생시킨다.

첫 예외의 경우

```shell
ch08.CloseException: CloseException 발생
	at ch08.CloseableResource.close(TryWithResourceEx.java:33)
	at ch08.TryWithResourceEx.main(TryWithResourceEx.java:7)
```

일반적인 예외 발생과 같은 형태로 출력되었지만 두번째는 출력형태가 조금 다른 것을 알 수 있다.

```shell
ch08.WorkException: WorkException 발생
	at ch08.CloseableResource.exceptionWork(TryWithResourceEx.java:28)
	at ch08.TryWithResourceEx.main(TryWithResourceEx.java:17)
	Suppressed: ch08.CloseException: CloseException 발생
		at ch08.CloseableResource.close(TryWithResourceEx.java:33)
		at ch08.TryWithResourceEx.main(TryWithResourceEx.java:16)
```

먼저 `exceptionWork()`메서드에서 발생한 예외에 대한 내용이 출력되고<br>
`close()`메서드에서 발생한 예외는 `억제된(Suppressed)`이란 의미의 머리말과 함께 출력되었다.

두 예외가 동시에 발생할 수는 없기 때문에, 실제 발생한 예외를 `WorkException`으로 하고<br>
`CloseException`은 억제된 예외로 다룬다.

억제된 예외에 대한 정보는 실제로 발생한 예외인 `WorkException`에 저장된다.

`Exception`클래스와 `Error`클래스의 공통 조상인 `Throwable`클래스에 정의된<br>
메서드 중에 억제된 예외와 관련된 것들은 다음과 같다.

1. void addSuppressed(Throwable exception) // 억제된 예외를 추가
2. Throwable[] getSuppressed() // 억제된 예외(배열)를 반환

⭐ 이를 `try-with-resources`문이 아닌 기존 `try-catch-finally`만으로 사용했다면<br>
⭐ 먼저 발생한 `WorkException`은 무시되고, 마지막 발생 예외인 `CloseException`에 대한 내용만 출력될 것이다.
