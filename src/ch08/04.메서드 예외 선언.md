# 04. 메서드 예외 선언
> 예외를 메서드에 선언하는 것은 실제로 예외를 처리하는 것이 아닌, 예외를 처리해야함을 알려주는 것이다.

즉 이 메서드를 호출하면 이러한 예외가 발생할 수 있으니<br>
이 메서드를 호출하는 쪽에서 예외를 처리해야 한다 알려주는 것이다.

다시말해 예외 처리를 호출한 쪽으로 떠넘기는 것이다.

```java
void method() throws Exception1, Exception2, ... ExceptionN {
    ...
}
```

아래처럼 모든 예외의 최고조상인 `Exception`클래스를 메서드에 선언하면<br>
이 메서드에서 모든 종류의 예외가 발생할 수 있다는 의미이다.

```java
void method() throws Exception {
    ...
}
```

---

`ch07/05.오버라이딩.md`에서 학습한 것처럼 오버라이딩할 때는 단순히 선언된 예외의 개수가 아니라<br>
해당 예외 클래스의 상속관계까지 고려해야 한다.

이렇듯 메서드를 작성할 때 발생할 가능성이 있는 예외를 선언부에 명시하여<br>
메서드를 사용하는 쪽에서 이에 대한 처리를 하도록 강요하기에, 견고한 프로그램 코드를 작성할 수 있다.

---

`code/ExceptionEx.java`를 살펴보면

예외가 발생한 다음 메서드에서 잘못 입력된 파일이름을 다시 입력 받도록 하였다.

```java
static File createFile(String fileName) throws Exception {
    ...
}
```

`createFile`메서드에 예외를 선언하였기에, `main`메서드에서 `try-catch`문으로<br>
생성된 `Exception`객체를 처리하도록 설계되었다.

```java
public static void main(String[] args) {
    try {
        File f = createFile(args[0]);
        System.out.println(f.getName() + "파일이 생성 완료");
    } catch (Exception e) {
        System.out.println(e.getMessage() + " 재입력 바랍니다.");
    }
}
```

```shell
> java ExceptionEx.java 
Index 0 out of bounds for length 0 재입력 바랍니다.
> java ExceptionEx.java ""
유효하지 않은 파일명 재입력 바랍니다.
> java ExceptionEx.java test1.txt 
test1.txt파일이 생성 완료
> java ExceptionEx.java test2.md
test2.md파일이 생성 완료
```

⭐ 위 예제처럼 예외가 발생한 메서드 호출 시 넘겨받아야 할 값(`fileName`)을 다시 받아야 할 경우<br>
⭐ 메서드 내에서 자체 해결이 안되기에 예외를 메서드에 선언하여 호출한 메서드에서 처리하도록 한다.

⭐ 메서드 내에서 자체적으로 처리가 가능한 경우, 내부에 `try-catch`문을 사용한다.
