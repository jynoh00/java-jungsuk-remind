# 04. 스택 오버플로우

`02.메모리 영역`에서 설명한 것처럼, 메서드는 호출 스택 영역에 생성된다.<br>
call stack의 크기는 유한하기에 다음과 같은 재귀호출 시 스택의 범위를 넘어서는 스택 오버플로우가 발생할 수 있다.

```java
public class StackOverFlow {
    public static void main(String[] args) {
        System.out.println("factorial: " +
                factorial(4));
    }

    ...

    private static int factorial(int n) {
        if (n == 1) return 1;
        return n * factorial(n - 1);
    }
```

파라미터 `n`의 값이 `0`일 경우, `if`문의 조건식이 절대 참이 될 수 없어 계속해서 재귀호출이 일어나고<br>
콜 스택에 계속해서 데이터가 쌓여가게 된다. 이는 어느 시점에 이르러 결국 스택 저장 한계를 넘게 되고<br>
`Stack OverflowError`가 발생하게 된다.

매개변수 `n`의 값이 큰 경우에도 너무 많은 재귀호출로 인해, 콜 스택의 저장 한계를 넘어 `Stack OverflowError`가 발생한다.

---

어떤 값이 입력으로 들어와도 에러없이 처리되는 견고한 코드를 위해<br>
⭐ 매개변수의 `유효성 검사`가 중요하다.

```java
private static int validationFactorial(int n) {
    if (n <= 0 || n > 12) return -1;

    if (n == 1) return 1;
    return n * factorial(n - 1);
}
```

`n`의 상한을 `12`로 정한 이유는 `13!`의 값이 `int`의 최대값(약 20억)보다 크기 때문이다.

---

재귀 호출이 아닌 반복문으로 `factorial`을 구현한 아래 메서드는<br>
재귀 호출과 달리 많은 수의 반복에도 스택 오버플로우 에러와 같은 메모리 부족 문제를 겪지 않는다.

```java
private static int loopFactorial(int n) {
    int result = 1;
    while (n != 1) {
        result *= n--;
    }
    return result;
}
```

⭐ 속도 또한 매번 새로운 메모리 공간을 형성하는 재귀호출 방식보다 빠를 수 밖에 없다.
