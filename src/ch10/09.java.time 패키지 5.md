# 08. java.time 패키지 5

### Instant

`Instant`클래스는 에포크 타임 (epoch time, 1970-01-01 00:00:00 UTC)부터<br>
경과된 시간을 나노초 단위로 표현한다, 단일 진법으로만 다루어 계산하기 쉽다. (사람이 사용하는 날짜와 시간 대비)

```java
Instant now = Instant.now();
Instant now2 = Instant.ofEpochSecond(now.getEpochSecond());
Instant now3 = Instant.ofEpochSecond(now.getEpochSecond(), now.getNano());
```

출력 결과는 아래와 같다. `System.out.println(@);`

```bash
2026-03-27T09:17:42.642183Z
2026-03-27T09:17:42Z
2026-03-27T09:17:42.642183Z
```

필드의 값을 가져오고자 할 경우

```java
long epochSec = now.getEpochSecond();
int nano = now.getNano();
```

`Instant`는 시간을 초 단위와 나노초 단위로 나누어 저장한다. 따라서 데이터베이스의 타임스탬프처럼<br>
밀리초 단위의 에포크 타임을 필요로 하는 경우를 위해 아래와 같은 메서드 또한 정의되어 있다.

```java
long toEpochMilli()
```

`Instant`는 기존 `Date`를 대체하기 위한 것이며, `Java 8`부터<br>
`Date`에 `Instant`로 변환할 수 있는 메서드가 추가 되었다.

```JAVA
static Date from(Instant instant) // Instant -> Date
Instant toInstant() // Date -> Instant
```

### LocalDateTime

`LocalDate`와 `LocalTime`을 합쳐놓은 것이 `LocalDateTime`이다.

다음은 `LocalDateTIme`을 만들 수 있는 여러 방법에 대한 코드이다.

```java
LocalDate date = LocalDate.of(2026, 3, 27);
LocalDate time = LocalTime.of(12, 34, 56);

LocalDateTime dt = LoCalDateTime.of(date, time);
LocalDateTime dt2 = date.atTime(time);
LocalDateTime dt3 = time.atDate(date);
LocalDateTime dt4 = date.atTime(12, 34, 56);
LocalDateTime dt5 = time.atDate(LocalDate.of(2026, 3, 27));
LocalDateTime dt6 = date.atStartOfDay(); // 2026-03-27 00:00:00, = date.atTime(0,0,0);
```

`LocalDateTime` 또한 날짜와 시간을 직접 지정할 수 있는 `of()`, `now()` 메서드가 존재한다.

```java
LocalDateTime dateTime = LocalDateTime.of(2026, 3, 27, 12, 34, 56);
LocalDateTime today = LocalDateTime.now();
```

`LocalDateTime`을 반대로 변환할 수도 있다.

```java
LocalDateTime dt = LocalDateTime.now();
LocalDate ld = dt.toLocalDate();
LocalTime lt = dt.toLocalTime();
```

### ZonedDateTime

`LocalDateTime`에 시간대(`time-zone`)를 추가한 것이 `ZonedDateTime`이다.<br>
기존 `TimeZone`클래스로 다루었던 시간대를 `time`패키지에선 `ZoneId`라는 클래스를 통해 다룬다.

`LocalDate`에 `atTime()`을 사용해 시간 정보를 추가하여 `LocalDateTime`을 얻는 것처럼,<br>
`LocalDateTime`에 `atZone()`을 사용해 시간대 정보를 추가하여 `ZonedDateTime` 객체를 얻을 수 있다.

```java
ZoneId zid = ZoneId.of("Asia/Seoul");
ZonedDateTime zdt = dateTime.atZone(zid);

System.out.println(zdt); // 2026-03-27T18:35:36.327713+09:00[Asia/Seoul]
```

`LocalDate`의 `atStartOfDay()`메서드 매개변수로 `ZoneId`를 지정하여도, `ZonedDateTime`을 얻는다.

```java
ZonedDateTime zdt = LocalDate.now().atStartOfDay(zid); // 2026-03-27T00:00+09:00[Asia/Seoul]
```

특정 시간대의 시간을 알고 싶다면 다음처럼 할 수 있다.

```java
ZoneId nyId = ZoneId.of("America/New_York");
ZonedDateTime nyTime = ZonedDateTime.now().withZoneSameInstant(nyId);
// 2026-03-27T05:39:44.147120-04:00[America/New_York]
```

`now()` 대신 `of()`를 사용하여 특정 날짜와 시간 또한 지정 가능하다.

### OffsetDateTime

`ZonedDateTIme`에서 `ZoneId`로 구역을 표현하였는데, `OffsetDateTime`에서는<br>
`ZoneId`가 아닌 `ZoneOffset`을 사용한다.

`ZoneId`에는 일광 절약 시간과 같은 시간대와 관련된 규칙들을 포함하고 있지만<br>
`ZoneOffset`은 단지 시간대를 시간의 차이로만 구분한다.

```java
ZoneOffset krOffset = ZonedDateTime.now().getOffset();
int krOffsetInSec = krOffset.get(ChronoField.OFFSET_SECONDS);
// 32400, 서울(+9:00:00) -> 60*60*9 = 32400 second
```

컴퓨터에게는 변함없이 일관된 시간 체계를 유지하는 것이 안전하기에, 이를 사용하며

같은 지역 내 컴퓨터 간 데이터 송수신에는 전송 시간을 표현하기에 `LocalDateTime`으로 충분하지만<br>
서로 다른 시간대에 존재하는 컴퓨터간 통신에는 `OffsetDateTime`이 필요하다.

```java
ZonedDateTime zdt = ZonedDateTime.of(date, time, zid);
OffsetDateTime odt = OffsetDateTime.of(date, time, krOffSet);

// ZonedDateTime에서 OffsetDateTime으로 변환
OffsetDateTime odt = zdt.toOffsetDateTime();
```

---

추가로 `ZonedDateTime`에서 날짜와 시간 관련 클래스를 변환하여 추출하는 메서드 또한 존재하며

```java
LocalDate toLocalDate()
LocalTime toLocalTime()
LocalDateTime toLocalDateTime()
OffsetDateTime toOffsetDateTime()
long toEpochSecond()
Instant toInstant()
```

`GregorianCalendar`와 가장 유사한 `ZonedDateTime`이기에<br>
두 사이의 변환 방법만 알고 있다면, 위에 나열환 메서드를 이용하여 다른 날짜와 시간 클래스들로 변환 가능하다.

```java
// ZonedDateTime -> GregorianCalendar
GregorianCalendar from(ZonedDAteTime zdt)
    
// GregorianCalendar -> ZonedDateTime
ZonedDateTime toZonedDateTime()
```
