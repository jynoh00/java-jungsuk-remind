# 02.Object 클래스 2

### 4. clone()

`clone()`메서드는 자신을 복제하여 새로운 인스턴스를 생성하는 일을 한다.

인스턴스에 대해 작업을 수행할 때, 기존 인스턴스는 보존하고 `clone()`을 이용해 새로운 인스턴스를 생성하여<br>
작업을 한다면 작업 이전의 값이 보존되므로<br>
작업에 실패해서 `원래의 상태로 되돌리거나` 변경되기 `전 값을 참고`하는데 도움이 된다.

`Object`클래스에 정의된 `clone()`은 단순히 `인스턴스 변수의 값만` 복사하기 때문에<br>
참조타입의 인스턴스 변수가 있는 클래스는 완전히 복제가 이루어지지 않는다.

이를 `얕은 복사(shallow copy)`라 한다.

```java
package ch09;

public class CloneEx {
    public static void main(String[] args) {
        Point original = new Point(3, 5);
        Point copy = (Point) original.clone();

        System.out.println(original);
        System.out.println(copy);
    }
}


class Point implements Cloneable { // Cloneable 구현체가 아니라면, clone 시 null이 반환됨 -> clone 불가
    int x, y;

    Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    public String toString() {
        return "x=" + x + ", y=" + y;
    }

    public Object clone() {
        Object obj = null;
        try {
            obj = super.clone();
        } catch (CloneNotSupportedException e) {}
        return obj;
    }
}
```

`Object`클래스의 `clone()`을 오버라이딩하려면
1. 복제할 클래스가 `Cloneable`인터페이스를 구현해야 하며
2. `clone()`을 오버라이딩하면서 접근 제어자를 `protected`에서 `public`으로 변경해야 한다.

그래야만 상속 관계가 없는(직접 조상 클래스가 `Object`) 클래스에서도 `clone()`을 호출할 수 있다.<br>
( `Object`클래스의 `clone()`은 `Cloneable`을 구현하지 않은 클래스 내에서 호출되면 예외를 발생시킨다 )

`Cloneable`인터페이스를 구현한 클래스의 인스턴스만 `clone()`을 통한 복제가 가능한 이유는<br>
인스턴스의 데이터를 보호하기 위해서이다. 즉 `Cloneable`의 구현체라는 것은 클래스 작성자가 복제를 허용했다는 의미

`JDK 5`부터 `공변 반환타입(covariant return type)`이 추가되었다.<br>
이 기능은 오버라이딩할 때 조상 메서드의 반환타입을 자손 타입으로 변경함을 허용하는 것이다.

```java
public Point clone() {
    Object obj = null;
    try {
        obj = super.clone();
    } catch (CloneNotSupportedException) {}
    
    return (Point) obj;
}
```

이처럼 `공변 반환타입`을 사용하면 조상의 타입이 아닌, 실제로 반환되는 자손 객체의 타입으로<br>
변환할 수 있어 번거러운 형태의 형변환이 줄어든다는 장점이 있다.

```java
int[] arr = {1, 2, 3, 4, 5};
int[] arrClone = arr.clone();
```

배열도 객체이므로 `Object`클래스를 상속 받으며, 동시에 `Cloneable`인터페이스와<br>
`Serializable`인터페이스가 구현되어 있다. 따라서 `Object`클래스의 멤버들을 모두 상속받는다.

배열 뿐 아니라 `java.util`패키지의 `Vector`, `ArrayList`, `LinkedList` 등<br>
여러 클래스들이 이와 같은 방식으로 복제가 가능하다.

```java
ArrayList list = new ArrayList();

ArrayList list2 = (ArrayList) list.clone();
```

`clone()`은 단순하게 객체에 저장된 값을 그대로 복제할 뿐,<br>
객체가 참조하고 있는 객체까지 복제하지 않는다. 즉 복사하는 건 참조하고 있는 참조값이기에<br>
기존 객체와 클론된 객체가 동일 객체를 참조하고 있게 되는 것이다.

이를 `얕은 복사(shallow copy)`라 하며, 얕은 복사에서는 원본을 변경하면 복사본도 영향을 받는다.

반면 원본이 참조하는 객체까지 복제하는 것을 `깊은 복사(deep copy)`라 하며<br>
깊은 복사에서는 원본과 서로 다른 객체를 참조하기 때문에 원본의 변경이 복사본에 영향을 미치지 않는다.

```java
class Circle implements Cloneable {
    Point p;
    double r;
    
    Circle(Point p, double r) {
        this.p = p;
        this.r = r;
    }
    
    public Circle clone() {
        Object obj = null;
        try {
            super.clone();
        } catch (CloneNotSupportedException e) { }
        
        return (Circle) obj;
    }
}
```

위 `Circle` 클래스를 통해 `c1` 인스턴스를 생성하고 복제해서 `c2`를 생성하면
```java
Circle c1 = new Circle(new Point(1, 1), 2.0);
Circle c2 = c1.clone();
```

`c1`과 `c2`는 같은 `Point`객체를 가리키게 되므로 완전한 복제라 볼 수 없다. (얕은 복사)

```java
public Circle clone() {
    Object obj = null;
    try {
        super.clone();
    } catch (CloneNotSupportedException e) { }
    
    Circle c = (Circle) obj;
    c.p = new Point(this.p.x, this.p.y);

    return c;
}
```

여러 방법으로 깊은 복사를 구현할 수 있겠지만, 그 중 하나로 위의 방법으로 깊은 복사 구현이 가능하다.

결과적으로 새로운 `Point`클래스의 인스턴스를 생성하였고 값으로 기존 인스턴스의 값들을 생성자에 넘겨<br>
`c1`과 `c2` 인스턴스는 멤버 참조변수까지 완전 독립된 깊은 복사가 완성되었다.

### 5. getClass()

`getClass()`메서드는 자신이 속한 클래스의 `Class`객체를 반환하는 메서드인데,<br>
`Class`객체는 이름이 `Class`인 클래스의 객체이다. `Class`클래스는 아래와 같다.

```java
public final class Class implements ... {
    ...    
}
```

`Class`객체는 클래스의 모든 정보를 담고 있으며 클래스 당 1개만 존재한다.

클래스 파일이 `클래스 로더(ClassLoader)`에 의해서 메모리에 올라갈 때, 자동으로 생성된다.<br>
( 클래스 로더는 실행 시에 필요한 클래스를 동적으로 메모리에 올리는 역할을 한다 )

먼저 기존 생성된 클래스 객체가 메모리에 존재하는지 확인하고, 있다면 객체의 참조를 반환하며<br>
없다면 `클래스 패스(classpath)`에 지정된 경로를 따라 클래스 파일을 찾는다.

못 찾으면 `ClassNotFoundException`이 발생하고, 찾으면 해당 클래스 파일을 읽어<br>
`Class`객체를 생성한다.

즉 파일 형태로 저장되어 있는 클래스를 읽어 `Class`클래스에 정의된 형식으로 변환하는 것이며,

클래스 파일을 읽어 사용하기 편한 형태로 저장해 놓은 것이 `Class`객체이고, 이 객체에는 클래스의 모든 정보가 담겨있다.

`Class`객체는 다음과 같은 방법들로 얻을 수 있다.

```java
class cObj = new Card().getClass(); // 생성된 객체로
class cObj2 = Card.class; // 클래스 리터럴(*.class)로
class cObj3 = Class.forName("Card"); // 클래스 이름으로
```

`forName()`의 경우 특정 클래스 파일(ex. 데이터베이스 드라이버)을 메모리에 올릴 때 주로 사용한다.<br>
문자열(클래스의 이름)만 바꾸면 코드 변경없이 다른 클래스의 객체를 생성할 수 있다는 것이 유용하다.

`Class`객체를 이용하면 클래스에 정의된 멤버의 이름이나 개수 등, 클래스에 대한 모든 정보를<br>
얻을 수 있기에 `Class`객체를 통해서 객체를 생성하고 메서드를 호출하는 등 보다 동적인 코드를 작성할 수 있다.

```java
final class Card {
    ...
}

...

// main
Card c = Card.class.newInstance();

Class cObj = c.getClass();
System.out.println(cObj.getName()); // Card
System.out.println(cObj.toGenericString()); // final class Card
System.out.println(cObj.toString()); // class Card
```

`Class`클래스를 찾아보면 이러한 기능을 포함한 많은 메서드가 정의되어 있다.
