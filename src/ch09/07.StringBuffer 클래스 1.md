# 07.StringBuffer 클래스 1
> `StringBuffer` 또한 `String`처럼 문자열을 다루기 위한 클래스이다.

문자열을 저장하기 위해 `char`배열을 인스턴스 변수로 선언해 놓고 있다.

`JDK 5`부터 `AbstractStringBuilder`가 `StringBuffer`의 조상으로 추가되어<br>
해당 클래스로 `char` 배열이 옮겨져서 사용되고 있다.

```java
// StringBuffer, StringBuilder의 조상 클래스
abstract class AbstractStringBuilder
        implements Serializable, CharSequence {
    char[] value; // String과 동일하게 JDK 9부터 byte[]로 바뀜
    ...
}
```

불변 문자열인 `String`과 다르게, `StringBuffer`는 `가변(mutable)`이라 `char`배열의 내용을 변경할 수 있다.

따라서 `StringBuffer`는 `char`배열의 내용을 변경하는 메서드가 다수 존재한다.<br>
`String`또한 문자열을 변경하는 메서드가 있지만, 기존 문자열이 변경되는 것이 아니라 항상 새로운 문자열을 저장하는<br>
`String`인스턴스를 반환했다. 반면 `StringBuffer`는 문자열의 내용을 변경할 수 있으므로

⭐ 새로운 `StringBuffer`인스턴스가 반환되지 않는다.

---

### 생성자

```java
AbstractStringBuilder(int capacity) {
    value = new char[capacity]; // JDK 9 부터 byte[]
}

public StringBuffer(int capacity) {
    super(capacity); // 버퍼 크기 지정
}

public StringBuffer() {
    super(16); // 버퍼 크기를 지정하지 않으면 16이 기본값으로 된다.
}

public StringBuffer(String str) {
    super(str.length() + 16); // 지정한 문자열의 길이보다 16 더 크게 버퍼를 생성
    append(str);
}
```

( `StringBuffer`를 생성할 때 버퍼의 크기가 결정되지만, 저장공간이 부족하면 자동으로 늘어난다. )

---

```java
StringBuffer sb = new StringBuffer("abc");
```

위와 같이 `StringBuffer`인스턴스를 참조변수 `sb`로 생성하면 메모리에 `a, b, c`가 배열에 담긴다.

```java
sb.append("123");
```

이후 문자열 `"123"`을 추가하면 동일 배열에 `1, 2, 3`이 추가된 `a, b, c, 1, 2, 3`이 된다.

`append()`의 반환타입은 `StringBuffer`로, 자신의 주소(`this`)를 반환한다.

```java
StringBuffer sb2 = sb.append("zz");
System.out.println(sb); // abc123zz
System.out.println(sb2); // abc123zz
```

때문에 `sb2`에 `sb.append("zz");` 반환값을 넘겨 참조변수를 선언하면<br>
`sb`와 `sb2` 모두 같은 인스턴스를 가리키는 참조변수가 된다.

따라서 하나의 `StringBuffer`인스턴스에 대해 아래와 같이 연속적으로 `append()`를 호출하는 것이 가능하다.

```java
StringBuffer sb = new StringBuffer("abc");
sb.append("123");
sb.append("zz");
```

```java
StringBuffer sb = new StringBuffer("abc");
sb.append("123").append("zz");
```

( `StringBuffer`클래스에는 `append()`처럼 객체 자신을 반환하는 메서드가 다수 있다 )

---

`String`클래스에서 인스턴스간 비교를 할 때, 등가비교연산자(`==`)와 `equals()`에 의한<br>
비교 차이점에 대해 자세히 알아보았었다.

`String`은 `Object`클래스의 `equals()`메서드를 오버라이딩하여 문자열의 내용을 비교하도록 구현되어 있지만

`StringBuffer`클래스는 `equals()`메서드를 오버라이딩하지 않았기에,<br>
`StringBuffer`의 `equals()`메서드를 사용하더라도 등가비교연산자(`==`)로 비교한 것과 같은 결과를 얻는다.

```java
StringBuffer sb = new StringBuffer("abc");
StringBuffer sb2 = new StringBuffer("abc");

System.out.println(sb == sb2); // false
System.out.println(sb.equals(sb2)); // false
```

반면 `toString()` 메서드는 오버라이딩되어 있기에, `StringBuffer`인스턴스에 `toString()`을<br>
호출하면, 담고 있는 문자열을 `String`으로 반환한다. 따라서 `StringBuffer`인스턴스에 담긴 문자열을 비교하기 위해

`StringBuffer`인스턴스에 `toString()`을 호출하여, `String`인스턴스를 얻은 후<br>
`equals()`메서드를 사용해서 비교해야 한다.

```java
StringBuffer sb = new StringBuffer("abc");
StringBuffer sb2 = new StringBuffer("abc");

System.out.println(sb.toString().equals(sb2.toString())); // true
```

`String`클래스의 메서드인 `boolean contentEquals(StringBuffer sb)`로도 비교 가능하다.

```java
System.out.println(sb.toString().contentEquals(sb2)); // true
```
