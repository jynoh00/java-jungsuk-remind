# 12. 래퍼(wrapper) 클래스 2

### `Number`클래스

`Number`클래스는 `abstract`클래스로 내부적으로 `숫자를 멤버변수로 갖는` 래퍼 클래스들의 조상이다.<br>
래퍼클래스의 상속계층도를보면, 기본형 중에서 숫자와 관련된 래퍼클래스들은 모두 `Number`클래스의 자손이다.

- `Object`
  - `Boolean`
  - `Chracter`
  - `Number`
    - `Byte`
    - `Short`
    - `Integer`
    - `Long`
    - `Float`
    - `Double`
    - `BigInteger`
    - `BigDecimal`

숫자 기본형 외에 `Number`클래스의 자손으로 `BigInteger`와 `BigDecimal`이 존재하는데

`BigInteger`는 `long`으로 다룰 수 없는 큰 범위의 정수를,<br>
`BigDecimal`은 `double`로도 다룰 수 없는 큰 범위의 부동 소수점 수를 처리하기 위한 것으로<br>
연산자의 역할을 하는 다양한 메서드들을 제공한다.

```java
public abstract class Number implements java.io.Serializable {
    public abstract int intValue();
    public abstract long longValue();
    public abstract float floatValue();
    public abstract double doubleValue();
    
    public byte byteValue() { return (byte) intValue(); }
    public short shortValue() { return (short) intValue(); }

    ...
```

`Number`클래스의 실제 소스는 위와 같은데, 객체가 가지고 있는 값을<br>
숫자와 관련된 기본형으로 변환하여 반환하는 메서드들을 정의하고 있다.

---

### 오토박싱`autoboxing` & 언박싱`unboxing`

기존 `JDK 5` 이전에는 `기본형`과 `참조형` 간의 연산이 불가능했기에<br>
래퍼클래스로 기본형을 객체로 만들어서 연산해야 했다.

```java
int i = 5;
Integer iObj = new Integer(7);

int sum = i + iObj; // error, 기본형과 참조형 간 덧셈 불가 (JDK 1.5 이전)
```

그러나 지금은 기본형과 참조형 간의 덧셈이 가능하다.<br>
컴파일러가 자동으로 변환하는 코드를 넣어주기 때문이다.

아래 코드는 컴파일러가 `Integer`객체를 `int`값으로 변환해주는 `intValue()`를 추가해준다.

```java
int i = 5;
Integer iObj = new Integer(7);

int sum = i + iObj; // int sum = i + iObj.intValue();
```

이외에도 내부적으로 객체 배열을 가지고 있는 `Vector`클래스나<br>
`ArrayList`클래스에 기본형 값을 저장해야할 때나 형변환이 필요할 때도

⭐ 컴파일러가 자동적으로 코드를 추가해 준다.

⭐ 기본형 값을 래퍼 클래스의 객체로 자동 변환해주는 것을 오토박싱(`autoboxing`),<br>
⭐ 반대로 래퍼 클래스의 객체를 기본형 값으로 자동 변환해주는 것을 언박싱(`unboxing`)이라 한다.

```java
ArrayList<Integer> list = new ArrayList<Integer>();

list.add(10); // 오토박싱 : list.add(Integer.valueOf(10));
int value = list.get(0); // 언박싱 : int value = list.get(0).intValue();
```

위 코드처럼 기본형값을 래퍼클래스의 객체로 변환하지 않아도 되므로 편리하다.

---

```java
int i = 10;

// 기본형 -> 참조형으로 형변환 *( 형변환()은 생략 가능하다 )
Integer intg = (Integer) i; // intg = Integer.valueOf(i);
Object obj = (Object) i; // obj = (Object) Integer.valueOf(i);, 조상 클래스로의 형변환

Long lng = 100L; // lng = Long.valueOf(100L);

// 참조형과 기본형 간의 연산 가능
int i2 = intg + 10; // intg.intValue() + 10;
long l = intg + lng; // 참조형 간의 덧셈 또한 가능, (long) intg.intValue() + lng.longValue();

Integer intg2 = Integer.valueOf(20);
int i3 = (int) intg2; // 참조형을 기본형으로 형변환 가능 (형변환 생략 가능), intg2.intValue()

Intger intg3 = intg2 + i3;
```

결국 이러한 기능은 컴파일러가 제공하는 편의 기능일 뿐, 자바의 원칙이 바뀐 것은 아니다.<br>
생성자가 없는 클래스에 컴파일러가 기본 생성자를 자동적으로 추가해 주듯이<br>
간략하게 작성된 구문을 컴파일러가 원래의 구문으로 변경해 주는 것이다.
