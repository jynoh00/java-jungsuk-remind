# 18. java.math 패키지

### 1. `java.math.BigInteger`

가장 큰 정수형 타입인 `long`으로 표현할 수 있는 값은 10진수로 19자리 정도이다.<br>
해당 값도 충분히 큰 값이지만, 과학적 계산에서는 더 큰 값을 다뤄야할 때가 있다. 이에 `BigInteger`를 사용한다.

`BigInteger`는 내부적으로 `int`배열을 사용해 값을 다룬다.<br>
따라서 `long`타입보다 큰 값을 다룰 수 있으나 성능은 `long`타입보다 떨어질 수 밖에 없다.

```java
final int signum; // 부호: 1(양수), 0, -1(음수) 중 하나
final int[] mag; // 값(magnitude)
```

`String`과 마찬가지로, `BigInteger` 또한 불변(`immutable`)값을 저장한다.

또한, 모든 정수형과 마찬가지로 `BigInteger`역시 값을 `2의 보수` 형태로 표현한다.<br>
부호를 따로 저장하고, 배열에는 값 자체만을 저장한다는 것이다.

따라서 부호만 다른 두 값의 `mag`는 동일하며, `signum`만 다른 값을 가진다.

---

```java
BigInteger val;
val = new BigInteger("12345678901234567890"); // 문자열로 생성
val = new BigInteger("FFFF", 16); // n진수(radix) 문자열로 생성
val = BigInteger.valueOf(1234567890L); // 숫자로 생성
```

`BigInteger`를 생성하는 방법으로, 문자열로 숫자를 표현하는 것이 일반적이다.
⭐ 정수형 리터럴로는 표현할 수 있는 값의 한계가 있기 때문이다.

---

`BigInteger`를 문자열, 또는 `byte[]`배열로 변환하는 메서드는 다음과 같다.

```Java
String toString() // 문자열로 변환
String toString(int radix) // 지정된 진법(radix)의 문자열로 반환
byte[] toByteArray() // byte 배열로 변환
```

앞서 살펴본 것 처럼 `Number` 클래스를 상속받는데, Number로부터 상속받은 기본형 변환 메서드들 또한 존재한다.

```java
byte byteValueExact()
int intValueExact()
long longValueExact()
```

주의할 점은 정수형 변환 메서드 중에서 이름 끝에 `Exact`가 붙은 것들은<br>
변환 결과가 변환한 타입의 범위에 속하지 않으면 `ArithmeticException`을 발생시킨다는 것이다.

---

다음은 `BigInteger`의 기본적인 연산을 수행하는 메서드들이다.

```java
BigInteger add(BigInteger val) // this + val
BigInteger subtract(BigInteger val) // this - val
BigInteger multiply(BigInteger val) // this * val
BigInteger divide(BigInteger val) // this / val
BigInteger remainder(BigInteger val) // this % val
```

앞서 언급한 것처럼 `BigInteger`는 불변이기에, 반환 타입이 `BigInteger`란 것은<br>
새로운 인스턴스가 반환된다는 뜻이다.

( `BigInteger`또한 `Integer`처럼 캐시 기능이 있다,<br>
`-16~16`범위 값이면 `valueOf()`가 캐시된 객체를 반환한다 )

아래는 비트 연산 메서드들이다.<br>
큰 숫자를 다루기에 성능을 향상시키기 위한 비트단위 연산 메서드들을 많이 가지고 있다.

```java
int bitCount() // 2진수 표현 시 1의 개수 (음수는 0의 개수)를 반환
int bitLength() // 2진수 표현 시 값을 표현하는데 필요한 bit수를 반환
boolean testBit(int n) // 우측에서 n+1번째 비트가 1이면 true, 0이면 false
BigInteger setBit(int n) // 우측에서 n+1번째 비트를 1로 변경
BigInteger clearBit(int n) // 우측에서 n+1번째 비트를 0으로 변경
BigInteger flipBit(int n) // 우측에서 n+1번째 비트를 전환 (1->0, 0->1)
```

( 이외에도 기본적인 `and, or, xor, not`과 같은 비트연산자를 구현한 메서드 또한 가지고 있다 )

---

정수가 짝수인지 확인할 때, 보통 정수를 `2`로 나눈 나머지가 `0`인지 확인한다.

```java
BigInteger bi = new BigInteger("4");
if (bi.remainder(new BigInteger("2")).equals(BigInteger.ZERO)) {
    // ...    
}
```

하지만 `BigInteger`에도 이러한 로직을 적용하면 위 코드처럼, 비효율적이며 코드가 복잡해진다.

따라서 짝수는 가장 오른쪽 비트가 `0`이기에, 이러한 로직을 차용하여 아래처럼 작성하는 것이 효율적이다.

```java
BigInteger bi = new bigInteger("4");

if (!bi.testBit(0)) { // 우측에서 0+1번째 비트가 0이면 false, 1이면 true
    // ...     
}
```

이처럼 `BigInteger`는 가능하면 산술연산 대신 비트연산으로 처리하도록 노력해야 한다.

( `BigInteger` 사용 예시 : `code/BigIntegerEx.java` )

### 2. `java.math.BigDecimal`

`double`타입으로 표현할 수 있는 값은 상당히 범위가 넓지만<br>
⭐ 정밀도가 최대 13자리 밖에 되지 않으며, 실수형의 특성상 오차를 피할 수 없다.

`BigDecimal`은 실수형과 다르게 정수를 이용하여 실수를 표현한다.

⭐ 앞서 배운 내용에서 실수의 오차는 10진 실수를 2진 실수로 정확히 변환할 수 없는 경우에서 발생하기에<br>
실수를 오차가 없는 2진 정수로 변환하여 다루는 것이다.

실수를 정수와 10의 제곱의 곱 형태로 표현한다.

### $정수 \times 10^{-scale}$

`scale`은 `0~Integer.MAX_VALUE`사이 범위에 있는 값이며,<br>
`BigDecimal`은 정수를 저장하는데 `BigInteger`를 사용한다.

( `BigDecimal` 또한 `BigInteger`처럼 불변(`immutable`)이다 )

```java
private final BigInteger intVal; // 정수 (unscaled value)
private final int scale; // 지수(scale)
private transient int precision; // 정밀도(precision) - 정수의 자릿수
```

`123.45`를 예로 살펴보면, `12345*10^-2`으로 표현가능하며 이 값이 `BigDecimal`에<br>
`intVal`는 `12345`, `scale`은 `2`가 되는 것이다.

그리고 `precision`의 값은 `5`가 되는데, 이 값은 정수의 전체 자리수를 의미한다.

```java
BigDecimal val = new BigDecimal("123.45");
System.out.println(val.unscaledValue()); // 12345
System.out.println(val.scale()); // 2
System.out.println(val.precision()); // 5
```

---

```java
BigDecimal val;
val = new BigDecimal("123.4567890"); // 문자열로 생성
val = new BigDecimal(123.456); // double타입 리터럴로 생성
val = new BigDecimal(123456); // int, long타입의 리터럴로 생성
val = BigDecimal.valueOf(123.456); // valueOf(double)를 통한 생성
val = BigDecimal.valueOf(123456); // valueOf(int)를 통한 생성
```

`BigInteger`와 마찬가지로, 문자열을 통해 생성하는 것이 일반적이다.

⭐ 주의할 점은 `double`타입의 값을 매개변수로 갖는 생성자를 사용하면, 오차가 발생할 수 있다.

```java
System.out.println(new BigDecimal(0.1));
System.out.println(new BigDecimal("0.1"));
```

```shell
0.1000000000000000055511151231257827021181583404541015625
0.1
```

---

`BigDecimal`을 문자열로 변환하는 메서드는 다음과 같은데

```java
String toPlainString() // 항상 다른 기호없이 숫자로만 표현
String toString() // 필요하면 지수형태로 표현할 수도 있다
```

대부분의 경우 동일 결과를 반환하지만, `BigDecimal`을 생성할 때<br>
`1.0e-22`와 같이 지수형태의 리터럴을 사용했을 때, 다른 결과를 얻을 수 있다.

`BigDecimal` 또한 `Number`를 상속받기에, 기본형으로 변환하는 메서드들을 가지고 있다.

```java
int intValue()
long longValue()
float floatValue()
double doubleValue()
```

`BigDecimal`을 정수형으로 변환하는 메서드 중, 이름 끝에 `Exact`가 붙은 것들은<br>
변환 결과가 변환 타입 범위에 속하지 않으면 `ArithmeticException`을 발생시킨다.

```java
byte byteValueExact()
short shortValueExact()
int intValueExact()
long longValueExact()
BigInteger toBigIntegerExact()
```

---

`BigDecimal` 역시 실수형에 사용할 수 있는 모든 연산자와, 수학적 계산을 위한 메서드들이 정의되어 있다.

```java
BigDecimal add(BigDecimal val) // this + val
BigDecimal subtract(BigDecimal val) // this - val
BigDecimal multiply(BigDecimal val) // this * val
BigDecimal divide(BigDecimal val) // this / val
BigDecimal remainder(BigDecimal val) // this % val
```

또한 마찬가지로, 매번 새로운 인스턴스가 반환된다. ( 불변(`immutable`)이기에 )

---

⭐ 중요한 것이 하나 있는데, 연산결과의 정수, 지수, 정밀도가 달라진다는 것이다.

```java
BigDecimal bd1 = new BigDecimal("123.456"); // 123456, 3, 6
BigDecimal bd2 = new BigDecimal("1.0"); // 10, 1, 2
BigDecimal bd3 = bd1.multiply(bd2); // 1234560, 4, 7
```

곱셈에서는 두 피연산자의 `scale`을 더하고, 나눗셈에서는 뺀다.<br>
덧셈과 뺄셈에서는 둘 중 자리수가 높은 쪽으로 맞추기 위해 두 `scale` 중 큰 쪽이 결과가 된다.

---

다른 연산들과 다르게, 나눗셈을 처리하기 위한 메서드는 다음처럼 다양한 버젼이 존재한다.

```java
BigDecimal divide(BigDecimal divisor)
BigDecimal divide(BigDecimal divisor, int roundingMode)
BigDecimal divide(BigDecimal divisor, RoundingMode roundingMode)
BigDecimal divide(BigDecimal divisor, int scale, int roundingMode)
BigDecimal divide(BigDecimal divisor, int scale, RoundingMode roundingMode)
BigDecimal divide(BigDecimal divisor, MathContext mc)
```

- 나눗셈의 결과를 어떻게 반올림(`roundingMode`)처리할 것인가와<br>
- 몇 번째 자리(`scale`)에서 반올림할 것인지를 지정할 수 있다.

`BigDecimal`이 오차없이 실수를 저장한다하여도, 나눗셈에서 발생하는 오차는 어쩔 수 없다.

`roundingMode`는 반올림 처리방법에 대한 것으로<br>
`BigDecimal`에 정의된 `ROUND_`로 시작하는 상수들 중에 하나를 선택해서 사용하면 된다.

```java
CEILING // 올림
FLOOR // 내림
UP // 양수일 때는 올림, 음수일 때는 내림
DOWN // 양수일 때는 내림, 음수일 때는 올림
HALF_UP // 반올림 (5이상 올림, 5미만 내림)
HALF_EVEN // 반올림 (반올림 자리의 값이 짝수면 HALF_DOWN, 홀수면 HALF_UP)
HALF_DOWN // 반올림(6이상 올림, 6미만 내림)
UNNECESSARY // 나눗셈의 결과가 딱 떨어지지 않으면, ArithmeticException 발생
```

`RoundingMode`는 이러한 상수들을 `열거형`으로 정의한 것으로, 나중에 추가되었다.<br>
가능하면 열거형 `RoundingMode`를 사용하도록 한다.

일반적으로 알고 있는 반올림은 `HALF_UP`이다.

⭐ 주의할 점은 `1.0/3.0`처럼 `divide()`로 나눗셈한 결과가 무한소수인 경우<br>
반올림 모드를 지정해주지 않으면 `ArithmeticException`이 발생한다.

---

#### `java.math.MathContext`

`MathContext`는 반올림 모드와 정밀도(`scale`)를 하나로 묶어 놓은 것이며 별 다른 의미는 없다.

⭐ `divide()`에서는 `scale`이 소수점 이하의 자리수를 의미하는데<br>
⭐ `MathContext`에서는 `precision`이 정수와 소수점 이하를 모두 포함한 자리수를 의미한다는 것만 주의하도록 한다.

```java
import java.math.BigDecimal;
import java.math.MathContext;

import static java.math.RoundingMode.HALF_UP;

public class BigDecimalEx {
    public static void main(String[] args) {
        BigDecimal bd1 = new BigDecimal("123.456");
        BigDecimal bd2 = new BigDecimal("1.0");

        System.out.println(bd1.divide(bd2, 2, HALF_UP));
        System.out.println(bd1.divide(bd2, new MathContext(2, HALF_UP)));
    }
}
```

```shell
123.46
1.2E+2
```

때문에 위 결과에서 `scale`이 `2`이면 나눗셈의 결과가 소수점 두 자리까지 출력되는데

`MathContext`를 사용한 결과는 `precision`을 가지고 반올림하므로<br>
`bd1`의 `precision`인 `12346`에서 세 번째 자리에서 반올림하여 `precision`은 `12000`이 아닌 `12`가 된다.

이후 `scale`이 반영되어 `1.2E+2`가 되는 것이다.

---

`BigDecimal`을 `10`으로 곱하거나, 나누는 대신 `scale`의 값을 변경하여 같은 결과를 얻을 수 있다.

```java
BigDecimal setScale(int newScale)
BigDecimal setScale(int newScale, int roundingMode)
BigDecimal setScale(int newScale, RoundingMode mode)
```

`setScale()`로 `scale`값을 줄이는 것은 10의 `n`제곱으로 나누는 것과 같기에,<br>
`divide()`를 호출할 때처럼 오차가 발생가능하며, 반올림 모드를 지정해 주어야 한다.

( `BigDecimal` 사용 예시 : `code/BigDecimalEx.java` )
