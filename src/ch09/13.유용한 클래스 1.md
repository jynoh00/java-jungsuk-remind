# 유용한 클래스 1
> `java.util`패키지에 있는 클래스 중 자주 사용되는 클래스들의 용도와 활용 방법에 대해 알아본다.

### 1. `java.util.Objects`

```java
import java.util.Objects;
```

`Object`클래스의 보조 클래스로, `Math`처럼 모든 메서드가 `static`이다.<br>
⭐ 객체의 비교나, 널 체크(`null check`)에 유용하다.

```java
static boolean isNull(Object obj)
static boolean nonNull(Object obj)
```
`isNull()`과 `nonNull()`은 해당 객체가 널인지 판단하는 메서드로<br>
`!Objects.isNull(obj)`과 `Objects.nonNull(obj)`이 동일한 코드이다.

또한 `requireNonNull()`메서드는 해당 객체가 널이 아니어야 하는 경우에 사용한다.

```java
static <T> T requireNonNull(T obj)
static <T> T requireNonNull(T obj, String message)
static <T> T requireNonNull(T obj, Supplier<String> messageSupplier)
```

만일 객체가 널이면, `NullPointerException`을 발생시킨다.<br>
이때 두 번째 매개변수로 지정하는 문자열은 예외의 메시지가 된다.

이를 활용한 매개변수의 유효성 검사 방법을 살펴보면,

```java
void setName(String name) {
    if (name == null)
        throw new NullPointerException("name must not be null.");
    this.name = name;
}
```

위와 같은 방식의 기존 매개변수 유효성 검사 방식에서, 아래처럼 코드를 줄일 수 있다.

```java
void setName(String name) {
    this.name = Objects.requireNonNull(name, "name must not be null.");
}
```

// `NullPointerException`은 `RuntimeException`의 자손 클래스이며, `unchecked` 예외이기에<br>
// `try-catch`가 강제되지 않는다.

<br>

`Object`클래스는 두 객체 간 등가 비교를 위한 `equals()`메서드만 존재하고<br>
대소 비교를 위한 `compare()`메서드가 없다. 이에 `Objects`클래스에 `compare()`메서드가 추가되었다.

```java
static int compare(Object a, Object b, Comparator c)
```

`compare()`메서드는 `a`, `b` 두 객체를 비교하는데 이때 사용할 비교 기준이 필요하다.<br>
이를 `Comparator`클래스의 객체가 역할을 하는데, 이는 추후 11장에서 자세히 알아본다.

```java
static boolean equals(Object a, Object b)
static boolean deepEquals(Object a, Object b)
```

`Object`클래스에 이미 정의되어 있는 `equals()`가 `Objects`클래스에도 있는데<br>
이 메서드의 장점은 `null`검사를 하는 조건식을 쓰지 않아도 된다는 것이다.

기존 `Object`클래스의 방식으로 `eqauls()` 등가 비교를 하려면

```java
if (a != null && a.equals(b)) {
    ...
}
```

위 코드 처럼 `equals()` 메서드를 부르는 `Object` 객체 `a`의 널 체크가 반드시 필요했다.

```java
if (Objects.equals(a, b)) {
        ...    
}
```

이를 `Objects.equals(a, b)`메서드를 활용하면, 클래스 메서드 내부에서<br>
`a`와 `b`의 널 체크를 수행하기 때문에 따로 널 검사를 위한 조건식을 넣지 않아도 된다.

```java
// Objects.equals()의 실제 코드
// a와 b가 모두 널이어도 참을 반환한다.
public static boolean equals(Object a, Object b) {
    return (a == b) || (a != null && a.equals(b));
}
```

⭐ 더 나아가 `deepEquals()`메서드는 객체를 재귀적으로 비교하기 때문에, `다차원 배열의 비교`도 가능하다.

```java
String[][] str2D = new String[][]{{"aaa", "bbb"}, {"AAA", "BBB"}};
String[][] str2D2 = new String[][]{{"aaa", "bbb"}, {"AAA", "BBB"}};
String[][] str2D3 = new String[][]{{"xxx", "bbb"}, {"AAA", "BBB"}};

System.out.println(Objects.equals(str2D, str2D2)); // false
System.out.println(Objects.deepEquals(str2D, str2D2)); // true
System.out.println(Objects.deepEquals(str2D, str2D3)); // false
```

2차원 배열을 비교할 때, `equals()`만으로는 불가하여 반복문과 함께 코드를 작성해야했지만,<br>
`deepEquals()`를 활용하면 간단히 끝낼 수 있다.

<br>

```java
static String toString(Object o) // null check가 포함되어 있음
static String toString(Object o, String nullDefault) // o가 null이면 사용할 기본값 지정
```

`toString()` 또한 `equals()`처럼 내부적으로 널 체크 코드가 추가된 것 빼고는 차이점이 없다.<br>
두 번째 메서드는 `o`가 널일 때, 대신 사용할 값을 지정할 수 있기에 유용하다.

<br>

마지막으로 `hashCode()` 역시 내부적으로 널 체크를 한 후, `Object`클래스의 `hashCode()`메서드를 호출한다.<br>
단 널일 때는 `0`을 반환한다.

```java
static int hashCode(Object o)
static int hash(Object... values)
```

보통 클래스에 선언된 인스턴스의 변수들의 `hashCode()`를 조합해서 반환하도록<br>
`hashCode()`를 오버라이딩하는데, 그 대신 매개변수의 타입이 가변인자인 두 번째 메서드를 사용하면 편리하다.<br>

( `hashCode()`에 대한 자세한 내용은 11장에서 알아보도록 한다 )

---

```java
System.out.println(Objects.hashCode(10)); // 10
```

`Objects`클래스의 `hashCode()`는 매개변수로 `Object`객체를 요구한다.<br>
이때 `primitive` `int`타입인 `10`을 인자로 넘겨주어도 실행이 되는데

이는 컴파일러가 `10`을 `오토박싱`하여 다음처럼 코드를 변경하기 때문이다.

```java
System.out.println(Objects.hashCode(Integer.valueOf(10)));
```

---

추가로, 다음처럼 `Objects`클래스의 메서드를 `static import`하여도

```java
import static java.util.Objects.*;
```

`equals()`, `deepEquals()`, `hashCode()`, `toString()`처럼<br>
`Object`클래스의 메서드와 이름이 같은 것들은 충돌이 생겨 컴파일러가 구별을 못한다.

따라서 클래스의 이름을 붙여 사용하여야 한다.
