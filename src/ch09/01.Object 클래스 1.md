# 01.Object 클래스 1
> 앞서 배웠듯이 `Object` 클래스는 모든 클래스의 조상이다. 주요 멤버들을 알아보도록 하겠다.

- `protected Object clone()`
: 객체 자신의 복사본을 반환

- `public boolean equals(Object obj)`
: 객체 자신과 객체 obj가 같은 객체인지 확인

- `protected void finalize()`
: 객체가 소멸될 때 가비지 컬렉터에 의해 자동적으로 호출된다.
: 이 때 수행되어야하는 코드가 있을 때 오버라이딩한다. (거의 사용x)

- `public Class getClass()`
: 객체 자신의 클래스 정보를 담고 있는 `Class`인스턴스를 반환

- `public int hashCode()`
: 객체 자신의 해시코드를 반환
 
- `public String toString()`
: 객체 자신의 정보를 문자열로 반환 

- `public void notify()`
: 객체 자신을 사용하려고 기다리는 쓰레드를 하나만 깨운다 

- `public void notifyAll()`
: 객체 자신을 사용하려고 기다리는 모든 쓰레드를 깨운다

- `public void wait()`
- `public void wait(long timeout)`
- `public void wait(long timeout, int nanos)`
: 다른 스레드가 `notify()`나 `notifyAll()`을 호출할 때까지 현재 쓰레드를 무한히 또는<br>
지정된 시간(`timeout`, `nanos`)동안 기다리게 한다. (timeout은 `1/000`s, nanos는 `1/10^9`s)

`Object`클래스는 멤버 변수가 없고 오직 위 11개의 메서드만 가지고 있다.<br>
( `notify()`, `notifyAll()`, `wait()`메서드는 13장 쓰레드에서 자세히 )

### 1. equals()

```java
public boolean equals(Object obj) {
    return (this == obj);
}
```

두 객체의 같고 다름을 참조변수의 값으로 판단한다. 따라서 서로 다른 두 객체를 `equals()`로<br>
비교할 경우 항상 `false` 결과를 얻게 된다.

즉 다음과 같은 경우에 `if`문 내부 블럭은 실행되지 않는다.

```java
Value v1 = new Value(10);
Value v2 = new Value(10);

if (v1.equals(v2)) System.out.println("실행x");
if (v2.equals(v1)) System.out.println("실행x");

v2 = v1; // v2 참조변수가 v1이 가리키는 객체를 가리키게 변경

if (v1.equals(v2)) System.out.println("실행");
if (v2.equals(v1)) System.out.println("실행");
```

`equals()`가 실제 멤버 변수의 값을 비교하도록 하고 싶다면, 오버라이딩하면 된다.

```java
class Person {
    long id;
    
    public boolean equals(Object obj) {
        if (obj instanceof Person p) return id == p.id;
        
        return false;
    }
    
    Person(long id) { this.id = id; }
}
```

`equals`메서드가 `Person`인스턴스의 주소값이 아닌 멤버 변수 `id`의 값을 비교하도록 하기 위해<br>
`equals`메서드를 오버라이딩한 것이다. 이를 통해 서로 다른 인스턴스일지라도 같은 `id`를 가진다면

`equals`메서드로 비교했을 때 `true`를 결과로 얻게 할 수 있다. ( `String`클래스의 `equals()`가 예시이다 )

⭐ 추가로 `instanceof`는 왼쪽 피연산자가 `null`이면 `false`를 반환하기에 널 확인을 하지 않아도 된다.

```java
if (obj != null && obj instanceof Person p) { // (obj != null) 불필요
    ...    
}
```

### 2. hashCode()

해당 메서드는 해싱(`hashing`)기법에 사용되는 `해시 함수(hash function)`를 구현한 것이다.<br>
해싱은 자료 구조 중 하나로, `다량의 데이터를 저장하고 검색`하는 데 유용하다.

해시 함수는 찾고자하는 값을 입력하면, 그 값이 저장된 위치를 알려주는 `해시 코드(hash code)`를 반환한다.<br>
( 주차장 키오스크에 차 번호(`찾고자 하는 값`) 입력 시, 주차된 위치(`hash code`) 반환)

일반적으로 해시 코드가 같은 두 객체가 존재하는 것이 가능하지만,<br>
`Object`클래스에 정의된 `hashCode()`는 객체의 주소값으로 해시 코드를 만들어 변환하기에<br>
`32bit JVM`에서는 서로 다른 두 객체가 결코 같은 해시 코드를 가질 수 없었지만

`64bit JVM`에서는 `8 byte` 주소값으로 `4 byte` 해시 코드를 만들기 때문에 중복될 수 있다.

앞서 살펴본 것처럼 클래스의 인스턴스 변수 값으로 객체의 같고 다름을 판단해야하는 경우라면<br>
`equals()`뿐만 아니라 `hashCode()`또한 적절히 오버라이딩해야 한다.

동일 객체라면 `hashCode()`를 호출했을 때의 결과값인 해시 코드도 같아야 하기 때문이다.

```java
String str1 = "abc";
String str2 = new String("abc");

/*
    str1.equals(str2) : true
    str1.hashCode() : 96354
    str2.hashCode() : 96354
*/

System.out.println(System.identityHashCode(str1));
System.out.println(System.identityHashCode(str2));
// 객체의 주소를 통한 해시코드 생성 -> 값이 다를 수 있다.
```

`String`클래스의 `hashCode()`또한 문자열의 내용이 같으면 동일 해시 코드를 반환하도록<br>
오버라이딩되어 있기 때문에, 문자열의 내용이 같은 `str1`, `str2`에 대해 동일 해시 코드를 얻는다.

### 3. toString()

```java
public String toString() {
    return getClass().getName() + "@" + Integer.toHexString(hashCode());
}
```

`toString()` 메서드의 원형으로, `toString()`을 호출하면 클래스 이름에 16진수의 해시 코드를 얻는다.

(`getClass()`, `hashCode()`를 인스턴스 생성 없이 바로 호출할 수 있는 이유는<br>
동일 `Object`클래스에 정의된 것이기 때문)

⭐ 조상의 메서드를 자손에서 오버라이딩할 때는 조상에 정의된 접근 범위보다 같거나 더 넓어야 하기에<br>
`toString()`을 오버라이딩하고자 할 때 무조건 `public` 접근 제어자만 가능하다.
