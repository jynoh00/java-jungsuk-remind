# 11. 래퍼(wrapper) 클래스 1
> 객체지향 개념에서 모든 것은 객체여야 한다. 기본형(`primitive type`) 값도 객체로 다뤄야 하는 경우가 있다.

매개변수로 객체를 요구하거나, 기본형 값이 아닌 객체로 저장해야할 때 혹은<br>
객체간의 비교가 필요할 때 등등의 경우 기본형 값들을 객체로 변환하여 작업을 수행해야 한다.

이때 사용되는 것이 `래퍼(wrapper) 클래스`이며 8개의 기본형을 대신할 수 있는 8개의 래퍼클래스가 있다.

---


### 1. 래퍼 클래스 : `Boolean`

펙토리 메서드 :
- `Boolean valueOf(boolean value)`
- `Boolean valueOf(String s)`

```java
Boolean b = Boolean.valueOf(true);
Boolean b2 = Boolean.valueOf("true");
```


---

```java
public final class Integer extends Number implements Comparable {
    ...
    private final int value;
    ...
}
```

위 코드는 `int`형의 래퍼 클래스인 `Integer`클래스 소스 일부이다.

코드에서 볼 수 있듯 래퍼 클래스들은 내부에 기본형 값을 저장하고 있으며,<br>
이 값은 문자열처럼 한번 저장하면 변경할 수 없는 불변(`immutable`)이다.

래퍼 클래스의 객체를 생성하는 방법은 크게 다음 2가지 방법이 있는데

```java
Integer i = new Integer(10);
Integer i = Integer.valueOf(10);
```

생성자로 생성하는 것은 `JDK 9`부터 권장하지 않으며 제거될 예정이기에,<br>
`valueOf()` 펙토리 메서드로 생성하는 것이 바람직하다.

---

`펙토리 메서드`란, 객체를 생성해서 반환하는 메서드를 말하며<br>
객체를 생성하지 않고 호출할 수 있어야 하기에 `static`메서드이다.

따라서 정적 펙토리 메서드(`static factory method`)라고도 한다.

```java
public static Integer valueOf(int i) {
    return new Integer(i);
}
```

위 코드는 아주 간단한 펙토리 메서드이나, 생성자와 다를게 없어 보인다.<br>
그럼에도 추후 변경사항이 발생했을 때나 다른 기능을 추가할 수 있는 등

여러 이점상 생성자보다 유리하다.

래퍼클래스의 펙토리 메서드는 캐싱 기능을 사용하며, `Integer`클래스의 `valueOf()`는 다음과 같이 작성되어 있다.<br>
( `IntegerCache.low`는 `-128`이며, `IntegerCache.high`는 `127`이다 )

```java
public static Integer valueOf(int i) {
    // low ~ high 사이의 i값이면 캐시(배열)에 미리 저장해놓은 객체를 반환한다. (성능)
    if (i >= IntegerCache.low && i <= IntegerCache.high)
        return IntegerCache.cache[i + (-IntegerCache.low)];
    return new Integer(i);
}
```

`Integer` 객체 배열(캐시)에 -128 ~ 127 범위의 `Integer`객체를 미리 생성해서 채워놓는다.

이후 이 범위 안의 값을 가진 `Integer`객체는 캐시에서 꺼내 반환하고, 범위를 벗어난 객체는 새로 생성하여 반환한다.

```java
System.out.println(Integer.valueOf(10) == Integer.valueOf(10)); // true
System.out.println(Integer.valueOf(200) == Integer.valueOf(200)); // false
```

위 코드를 실행해보면, 캐시 범위 내의 값인 10으로 펙토리 메서드를 실행해 `Integer`객체간 주소값을 비교해보면<br>
캐시에 저장된 동일 객체를 반환하기에 `true`값이 나온다.

그러나 캐시 범위를 벗어난 `200`을 펙토리 메서드로 객체들을 만들면, 늘 새로운 객체를 반환하므로<br>
`false`값의 결과를 얻는다.

---

```java
Integer i = Integer.valueOf(100);
Integer i2 = Integer.valueOf("100");

System.out.println(i == i2); // true
System.out.println(i.equals(i2)); // true
System.out.println(i.compareTo(i2)); // 0
System.out.println(i.toString()); // "100"

System.out.println(Integer.MAX_VALUE); // 2147483647
System.out.println(Integer.MIN_VALUE); // -2147483648

System.out.println(Integer.SIZE); // 32
System.out.println(Integer.BYTES); // 4
System.out.println(Integer.TYPE); // int
```

모든 래퍼 클래스들은 `equals()`가 오버라이딩되어 있어 주소값이 아닌 객체가 가지고 있는 값을 비교한다.

`오토박싱`이 된다 하여도 `Integer`객체에 비교 연산자를 사용할 수 없기에 `compareTo()`를 제공한다.<br>
`compareTo()`는 두 값이 같을 때 `0`, 좌측값이 클 때 `양수`, 좌측값이 작을 때 `음수`를 반환한다.

또한 `toString()` 역시 오버라이딩되어 있어, 객체가 가지고 있는 값을 문자열로 변환하여 반환한다.

외에도 `MAX_VALUE`, `MIN_VALUE`, `SIZE`, `BYTES`, `TYPE`등의 `static` 상수를 공통적으로 가지고 있다.
